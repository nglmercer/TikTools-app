Filters and selection ​

Purpose and prerequisites ​

Combine search, filters, counts and actions in a wrapping collection toolbar. Filtering belongs to the collection owner. Use the existing Vue workspace and its i18n provider. The preview mounts the real shared components in an isolated application frame; the documentation theme does not load desktop global CSS.

Try the example ​

  1. Load the preview or open the full demo.
  2. Change the state selector to inspect loading, empty, error, disabled, long text and mobile presentation where applicable. A state without a distinct rendering does not add an artificial behavior to the component.
  3. Use Tab, Enter, Escape and arrow keys according to the control. Check its accessible name, visible focus, and return focus when closing a popup.
  4. Change a value or invoke its action and inspect the resulting selection or output. Refresh or Reset restores demo state.

Executable source ​

This exact file is both compiled for the preview and included as the snippet. Its small state belongs to the example. Account, plugin and host logic stays in features/entities rather than shared UI.

vue
<script setup lang="ts">
defineOptions({ name: "FiltersExample" });
import { ref, computed } from 'vue';
import { useI18n } from 'vue-i18n';
import { exampleText } from './text.ts';
const { locale } = useI18n();
const t = computed(() => exampleText(locale.value));
const props = withDefaults(defineProps<{ state?: string }>(), { state: 'normal' });
const disabled = computed(() => props.state === 'disabled' || props.state === 'loading');
import CollectionToolbar from '@/shared/ui/collection-toolbar/CollectionToolbar.vue';
import BaseTextField from '@/shared/ui/text-field/BaseTextField.vue';
import BaseCheckbox from '@/shared/ui/checkbox/BaseCheckbox.vue';
const query = ref(''); const enabled = ref(false);
</script>
<template>
  <div class="component-example" :data-state="props.state"><CollectionToolbar :label="t.search" :count="'3'"><template #search><BaseTextField v-model="query" type="search" :aria-label="t.search" :disabled="disabled" /></template><BaseCheckbox v-model="enabled" :aria-label="t.enabled" :disabled="disabled" /></CollectionToolbar><output>{{ query }}</output></div>
</template>

Accessibility and recovery ​

Use a visible label or aria-label, preserve keyboard operation and avoid relying on color alone. Test at a narrow width and with long translated labels. For forms, bind the row's controlAttrs to the actual input so errors and required state remain associated. A disabled control cannot explain a failure on its own; show an adjacent status and a recovery action.

If a preview fails, close and reopen it, then Reset its own demo instance. Review the static API and source even when the demo is unavailable. Native dialogs, external services and operating-system integration require separate desktop tests. Return to the component guide.
