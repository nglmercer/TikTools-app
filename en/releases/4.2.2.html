TikTools 4.2.2 ​

Goal, publication status and prerequisites ​

Use these notes to review the implemented Variables changes and the release's remaining gates. Status reported on 13 November 2026: application compilation and CI checks are green; Linux installers now package successfully and Windows packaging passed, but the AppImage startup gate failed on a missing XKB runtime dependency and 4.2.2 is not published. No successful installer publication, uploaded checksum verification or update-feed promotion is claimed.

The build runs in hernan-lc/TikTools-app with RELEASE_REPO=nglmercer/TikTools-app as its intended publication target. Existing 4.2.1 candidate assets remain separate. For an available test release use the published RC3 prerelease; check the release list for actual downloadable assets.

These Cloud and collaboration features remain experimental. Source/candidate testing requires a separately built matching host, an isolated profile, saved non-secret Variables, current Cloud session/consent and the advertised native bridge. See development setup.

Implemented Variables changes ​

Variables uses the shared Changes panel. Send handles only selected saved native values; download refreshes only the cache. Applying a reviewed Cloud value and withdrawing its Cloud copy are separate actions. Withdrawal retains the local value and secret classification. Unsaved local drafts must be saved or discarded first, and older hosts without the bridge hide the control.

The host checks exact session, consent, local revision and target comparison. Queued edits can be replaced or cancelled. Epoch-fenced recovery handles uncertain uploads and withdrawal after a value becomes secret without replaying its previous value. Decision generations advance after acknowledgement. Unchecked Variables and other section queues remain outside the selected send.

Large integer values retain exact native text across browser editing and comparison/adoption. Saving an unrelated variable preserves untouched integer text. Types remain text, number, boolean, list and local secret. Secret or blocked values have no value diff, send or adopt control. This adapter has no field merge, force, history or autosync control.

Review steps and expected result ​

  1. In an isolated matching candidate, save a harmless text value such as demoGreeting = "Hello". Saving alone should stay local.
  2. Open Variables → Changes when the host announces support. Review the saved local/Cloud comparison and choose only the intended row for Send.
  3. Treat download as a cache update. Review and Apply separately before expecting the local value to change.
  4. Use explicit withdrawal to remove a Cloud copy. The local value and its secret classification should remain intact.
  5. If session, consent, revision or a target changes, refresh the comparison and review again. Resolve an uncertain outcome through its existing recovery path rather than repeating an upload as a new operation.

These are expected source behaviors, not newly executed production acceptance results.

CI corrections, recovery and unfinished work ​

The source corrects test-module ordering, a lifecycle fixture's prerelease SemVer opt-in and a test server's bounded complete-header read. Production plugin compatibility policy remains unchanged. The release workflow requires Linux AppImage startup with an isolated profile, installer content checks, immutable upload, downloaded checksums and signed-feed publication. The recovery run generated Linux installers after preventing nested linuxdeploy cleanup from deleting its parent's extraction directory. Its next check incorrectly required a FUSE installation classification while using extract-and-run. Recovery tooling now distinguishes extracted startup from mounted installation; the native updater still rejects extracted layouts. The single authorized rerun passed packaging and both CLI probes, then failed before frontend-ready because libxkbcommon-x11 could not be loaded. Its remaining work was cancelled to avoid spending minutes on a publication that could no longer proceed. The fix installs the XKB packages and bundles the dynamically loaded library with its dependencies; local Ubuntu loading checks pass. A complete corrected AppImage startup and release publication are still unverified; no further Actions run has been started.

Until packaging recovery and verified publication finish, use published assets and follow the updates guide. Keep profile backups; replacing a binary does not undo database migrations. For Variables failures preserve pending state, version and redacted request/error details using Diagnostics.

Teams nickname discovery and recipient-bound invitations still depend on backend 6a69c99 and migration 20261113000001_remote_invitation_recipients.sql. This application build does not deploy the backend. Automations Cloud transport, Overlay revisions, history/branch provenance and remaining collaboration presentation work are separate. The historical LIVE SQLite lock holder remains unidentified. Local/fake-account checks do not establish signed-in production sync or Teams compatibility.
