Organize automations ​

Goal and prerequisites ​

Build a small, understandable library that responds to LIVE events. You need a working desktop host. A real LIVE connection is needed to validate upstream events; plugin actions also require their plugin and service to be ready.

Understand the library ​

An Action is a reusable configured operation, such as writing a log line or playing a sound. An Event chooses a trigger, filters, cooldown and linked actions. A profile groups definitions for a workflow; only one profile pack is active at a time. Runtime Variables supply values that several actions can reuse.

  1. Open Automations and confirm the active profile before editing. Search Events and Actions separately so you know which kind of record you are selecting.
  2. Begin with the first logging rule. Create its action, then an event that references it.
  3. Choose a trigger supported by the current host. Use the field picker to add filters for that trigger. Multiple conditions narrow matching; they do not change the incoming payload.
  4. Set a cooldown and its scope. A global cooldown limits the rule across viewers; a per-user cooldown tracks viewers separately.
  5. Link the intended actions in order. The normal mode runs the chosen list; random mode selects an action from it. A delay action postpones later actions rather than slowing LIVE ingestion.
  6. Save, review any displayed definition changes, then explicitly enable the records you intend to run. Check the run history for the action name, outcome and error.

Every comparison can take a list of values instead of a single one. The default combines them as “any”: the condition passes when at least one value matches. Switch the quantifier to “all” when every value must match — for “is not” this reads “is none of”. A condition can also name a capture alias; the winning value is then available to action templates as {{ match.<alias> }} (or {{ match.<position> }} without an alias). Below the always-required conditions you can add up to four alternatives: groups whose conditions must all pass inside the group, where any single group is enough for the event to fire.

Tests can execute the configured effects. Read the selected action list before pressing Test or firing an event, especially for audio, HTTP, points and plugin operations. Use logging while learning.

Expected result and status ​

Local editing, execution, templates, profiles and history are available. Plugin triggers appear only while their supporting plugin is installed and enabled. Activation depends on the import surface and reviewed enabled values; inspect both events and actions before confirming. The Events/Actions Changes panel is a local reference comparison, not automatic Cloud upload.

Recovery ​

For no run, check active profile, enabled states, trigger, filters, cooldown and missing actions in that order. For a revision conflict, read the current saved definition and review again. Do not overwrite another person's update blindly. Export a known-good profile before broad changes.

Operational details ​

Before changing profiles or importing, read the activation rules by surface. Profile switching can enable members that you had individually disabled. Cooldown state is in memory, capped at 24 hours; missing viewer uniqueId shares one anonymous scope. The table clears when it reaches 8,192 retained keys, so overload or restart can allow extra runs. It is not a durable quota or replay guarantee.

Command line operations ​

Every operation in this guide is also available from the CLI — offline, scriptable and agent-friendly. Usage lines are parser syntax and stay in English in every locale.

CommandSummary
tiktools automation list [--kind event&#124;action&#124;all]list automation rules
tiktools automation context [--event-type t]template context available to rules
tiktools automation get <id> [--kind event&#124;action]read one rule
tiktools automation create --record json [--kind event&#124;action]create a rule
tiktools automation update <id> --record json [--kind event&#124;action]update a rule
tiktools automation delete <id> [--kind event&#124;action]delete a rule destructive
tiktools automation enable <id> [--kind event&#124;action]enable a rule
tiktools automation disable <id> [--kind event&#124;action]disable a rule
tiktools automation test (--id <id> &#124; --record json) [--kind event&#124;action] [--trigger t] [--event json]dry-run a rule against a sample event
tiktools automation fire --trigger <type> [--event json] [--record json]fire a trigger manually
tiktools automation moderation-penalty --points <delta>apply a moderation penalty in points
