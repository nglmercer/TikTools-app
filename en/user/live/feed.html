Read and inspect the LIVE feed ​

Goal and prerequisites ​

Find an event, inspect its fields and distinguish a paused display from a disconnected room. Start with a LIVE connection, or use events already present in the current feed. The feed is a bounded working view, not a complete recording of a broadcast.

Inspect activity ​

  1. Open Live feed and confirm the active creator in the connection status.
  2. Choose an event filter: all events, chat, gifts, likes, follows, joins or other social activity. Combine it with search to find an author, message, gift name or exact gift ID.
  3. Select Pause to stop automatic scrolling while you read. Events can continue arriving and the unread count can increase. This control does not disconnect TikTok or suspend automations.
  4. Select an event to open its inspector. Read the event type and available details before choosing automation fields. Not every event carries chat text, gift information or a viewer identity.
  5. Select a viewer's name or avatar to inspect their tracked profile. Use the inspector toggle if the details panel is hidden.
  6. Select Resume or the unread-event jump button to return to incoming activity. Clear the search and select all events when checking whether activity is arriving.

Use the labeled controls with keyboard focus where possible. Pausing scrolling helps when movement makes reading difficult. A missing avatar has an initials fallback; a picture is not needed to identify a viewer.

Expected result and status ​

Filtering and inspection are available. During heavy traffic, the interface can show a limited rendering window and report dropped UI events. These indicators describe the display; do not use its visible row count as an accounting total. Analytics queries persisted aggregates separately.

Recovery ​

If the feed is empty, remove filters, resume scrolling and check connection status. A quiet room may be healthy. Reconnecting to the same creator retains context; switching creator changes it. Clear empties the working feed and does not reset points or analytics. Investigate loss indicators through diagnostics, without assuming all missing display rows are missing upstream events.

Operational details ​

This version retains up to 300 displayed events and stages up to 900 while presentation waits. Retention evicts the oldest non-gift row first; gifts are evicted only when no other types remain. An older gift can therefore outlast a newer chat. Pausing scrolling does not stop ingestion or guarantee retention. Filters cannot restore evicted rows; a loss warning is evidence of an incomplete view, not permission to replay points or actions.
