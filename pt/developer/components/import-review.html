Importação e revisão ​

Objetivo e pré-requisitos ​

Leia um arquivo de tamanho limitado ou um documento colado, prepare os registros analisados e solicite uma importação explícita. A estrutura da interface nunca executa o conteúdo importado. Use o workspace Vue existente e seu provedor i18n. A prévia monta os componentes compartilhados reais em um quadro isolado do aplicativo; o tema da documentação não carrega o CSS global do desktop.

Experimente o exemplo ​

  1. Carregue a prévia ou abra a demonstração completa.
  2. Altere o seletor de estado para inspecionar carregamento, vazio, erro, desativado, texto longo e apresentação móvel quando aplicável. Um estado sem renderização distinta não acrescenta comportamento artificial ao componente.
  3. Use Tab, Enter, Escape e as setas conforme o controle. Verifique seu nome acessível, o foco visível e o retorno do foco ao fechar uma janela flutuante.
  4. Altere um valor ou execute a ação e inspecione a seleção ou saída resultante. Recarregar ou usar Reset restaura o estado da demonstração.
Exemplo: Importação e revisãodemo:settings

Carregando a interface…

API ​

As propriedades, os valores padrão, eventos, slots e declarações de modelo a seguir são gerados a partir do código-fonte do componente. Os tipos importados continuam vinculados a esse código, em vez de serem duplicados manualmente. Os atributos não declarados seguem o contrato de encaminhamento do componente; revise seu código antes de associar um evento nativo a um elemento envolvente.

Código-fonte executável ​

Este mesmo arquivo é compilado para a prévia e incluído como trecho de código. Seu pequeno estado pertence ao exemplo. A lógica de contas, plugins e host permanece em features/entities, fora da interface compartilhada.

vue
<script setup lang="ts">
defineOptions({ name: "ImportReviewExample" });
import { ref, computed } from 'vue';
import { useI18n } from 'vue-i18n';
import { exampleText } from './text.ts';
const { locale } = useI18n();
const t = computed(() => exampleText(locale.value));
const props = withDefaults(defineProps<{ state?: string }>(), { state: 'normal' });
const disabled = computed(() => props.state === 'disabled' || props.state === 'loading');
import BaseImportDialog from '@/shared/ui/import-dialog/BaseImportDialog.vue';
import BaseButton from '@/shared/ui/button/BaseButton.vue';
const open = ref(false); const staged = ref<Array<{ key: string; label: string }>>([]); const errors = ref<string[]>([]); const done = ref(false);
const tab = ref('manual');
function content(text: string) { try { const value: unknown = JSON.parse(text); if (!value || typeof value !== 'object') throw new Error(); staged.value = [{ key: 'demo', label: 'Demo' }]; errors.value = []; } catch { errors.value = [t.value.error]; } }
</script>
<template>
  <div class="component-example" :data-state="props.state"><BaseButton :disabled="disabled" @click="open = true">{{ t.open }}</BaseButton><BaseImportDialog v-model:open="open" v-model:tab="tab" :title="t.name" :tabs="[{ value: 'manual', label: t.open }]" :staged="staged" :errors="errors" :busy="props.state === 'loading'" :success="done ? t.ready : ''" :max-bytes="4096" @content="content" @import="done = true" /></div>
</template>

Acessibilidade e recuperação ​

Use um rótulo visível ou aria-label, preserve a operação pelo teclado e evite depender apenas da cor. Teste em uma largura estreita e com rótulos traduzidos longos. Nos formulários, vincule controlAttrs da linha ao campo real para manter a associação dos erros e do estado obrigatório. Um controle desativado não explica uma falha sozinho; mostre um status adjacente e uma ação de recuperação.

Se uma prévia falhar, feche-a e abra-a novamente, depois use Reset na própria instância da demonstração. Revise a API estática e o código mesmo quando a demonstração estiver indisponível. Diálogos nativos, serviços externos e integração com o sistema operacional exigem testes de desktop separados. Voltar ao guia de componentes.
