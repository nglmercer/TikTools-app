Organize automações ​

Objetivo e pré-requisitos ​

Crie uma biblioteca pequena e compreensível que responda a eventos de LIVE. Você precisa de um host de desktop funcional. Uma conexão real com uma LIVE é necessária para validar os eventos recebidos do serviço; ações de plugins também exigem que o plugin e seu serviço estejam prontos.

Entenda a biblioteca ​

Uma Action é uma operação configurada reutilizável, como escrever uma linha no registro ou tocar um som. Um Event define um acionador, filtros, intervalo de espera e ações vinculadas. Um perfil agrupa definições de um fluxo de trabalho; apenas um pacote de perfil fica ativo por vez. As Variables de execução fornecem valores que várias ações podem reutilizar.

  1. Abra Automations e confirme o perfil ativo antes de editar. Pesquise Events e Actions separadamente para saber qual tipo de registro está selecionando.
  2. Comece pela primeira regra de registro. Crie sua ação e depois um evento que a referencie.
  3. Escolha um acionador aceito pelo host atual. Use o seletor de campos para adicionar filtros desse acionador. Várias condições restringem as correspondências; elas não alteram os dados recebidos.
  4. Defina um intervalo de espera e seu escopo. Um intervalo global limita a regra entre todos os espectadores; um intervalo por usuário acompanha cada espectador separadamente.
  5. Vincule as ações desejadas na ordem. O modo normal executa a lista escolhida; o modo aleatório seleciona uma ação dela. Uma ação de atraso adia as ações seguintes, sem reduzir a velocidade de ingestão da LIVE.
  6. Salve, revise as alterações de definição exibidas e ative explicitamente os registros que pretende executar. Confira no histórico de execução o nome da ação, o resultado e o erro.

Toda comparação aceita uma lista de valores em vez de um único valor. A combinação padrão é “qualquer”: a condição é atendida quando pelo menos um valor corresponde. Mude o quantificador para “todos” quando todos os valores precisarem corresponder — com “não é”, isso significa “não é nenhum”. Uma condição também pode nomear um alias de captura: o valor vencedor fica disponível nos modelos de ação como {{ match.<alias> }} (ou {{ match.<posição> }} sem alias). Abaixo das condições sempre obrigatórias, você pode adicionar até quatro alternativas: grupos em que todas as condições precisam passar internamente, e basta um único grupo para o evento disparar.

Os testes podem executar os efeitos configurados. Leia a lista de ações selecionadas antes de pressionar Test ou disparar um evento, especialmente para áudio, HTTP, pontos e operações de plugins. Use registros enquanto aprende.

Resultado esperado e status ​

Edição local, execução, modelos, perfis e histórico estão disponíveis. Acionadores de plugins aparecem apenas enquanto o plugin correspondente está instalado e ativo. A ativação depende da superfície e dos valores enabled revisados; confira eventos e ações antes de confirmar. O painel Changes de Events/Actions é uma comparação com referência local, não um envio automático ao Cloud.

Recuperação ​

Quando não houver execução, verifique perfil ativo, estados de ativação, acionador, filtros, intervalo de espera e ações ausentes, nessa ordem. Para um conflito de revisão, leia a definição salva atual e revise novamente. Não sobrescreva a atualização de outra pessoa às cegas. Exporte um perfil que funcione antes de fazer alterações amplas.

Detalhes de operação ​

Antes de trocar perfil/importar, leia ativação por superfície. A troca pode ativar membros desativados individualmente. Cooldown fica em memória, limitado a 24 horas; sem uniqueId os espectadores compartilham escopo anônimo. A tabela esvazia ao atingir 8.192 chaves: sobrecarga ou reinício podem permitir execuções adicionais. Não é cota durável nem garantia contra replay.

Operações de linha de comando ​

Cada operação deste guia também está disponível na CLI — offline, scriptável e apta para agentes. As linhas de uso são sintaxe do parser e permanecem em inglês em todos os idiomas.

ComandoResumo
tiktools automation list [--kind event&#124;action&#124;all]listar as regras de automação
tiktools automation context [--event-type t]contexto de modelo disponível para as regras
tiktools automation get <id> [--kind event&#124;action]ler uma regra
tiktools automation create --record json [--kind event&#124;action]criar uma regra
tiktools automation update <id> --record json [--kind event&#124;action]atualizar uma regra
tiktools automation delete <id> [--kind event&#124;action]excluir uma regra destrutivo
tiktools automation enable <id> [--kind event&#124;action]ativar uma regra
tiktools automation disable <id> [--kind event&#124;action]desativar uma regra
tiktools automation test (--id <id> &#124; --record json) [--kind event&#124;action] [--trigger t] [--event json]testar uma regra em seco contra um evento de amostra
tiktools automation fire --trigger <type> [--event json] [--record json]disparar um gatilho manualmente
tiktools automation moderation-penalty --points <delta>aplicar uma penalidade de moderação em pontos
ComandoResumo
tiktools workflow listlistar os grafos de workflow salvos
tiktools workflow get <id>ler um grafo
tiktools workflow save --record jsoncriar ou substituir um grafo
tiktools workflow delete <id>excluir um grafo destrutivo
tiktools workflow enable <id>ativar um grafo
tiktools workflow disable <id>desativar um grafo
