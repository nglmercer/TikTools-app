Prepare overlays para o OBS ​

Objetivo e pré-requisitos ​

Projete um widget legível e conecte sua fonte de navegador local ao OBS. Você precisa do TikTools em execução, da capacidade de gateway de overlays e do OBS no mesmo computador para o endereço de loopback padrão. A saída ao vivo também precisa do evento recebido relevante ou de uma fonte de ranking configurada.

Projete e visualize ​

Experimente o editor de sobreposiçõesdemo:overlays

Carregando a interface…

↳

Sua tarefa Escolha uma sobreposição e altere seu design. Confira o resultado na prévia.

  1. Abra Sobreposições e leia o status do gateway. Escolha novos seguidores, presentes, chat, compartilhamentos, assinaturas, curtidas ou ranking.
  2. Edite camadas, texto visível, cores, espaçamento e opções de avatar no inspetor de design. Use contraste suficiente e tamanho legível na resolução real da transmissão.
  3. Reproduza a prévia para inspecionar o layout. O conteúdo da prévia ajuda a avaliar o design; não comprova a entrega de eventos da LIVE.
  4. Use os controles Desfazer/Refazer para edições locais e depois Salvar design. Trocar o tipo de widget com alterações não salvas solicita que você as descarte.
  5. No painel de prévia/fonte, copie a URL da fonte. A URL exibida mascara sua credencial; use o controle de cópia para obter a URL utilizável. Mantenha essa URL privada.
  6. Adicione uma fonte de navegador no OBS e cole a URL copiada. Mantenha o TikTools em execução e valide um evento relevante antes de depender dele durante uma transmissão.

O gateway padrão é 127.0.0.1:17452. Uma URL de loopback se refere ao computador que executa a fonte de navegador, portanto copiá-la para outro computador não alcança esse host automaticamente. Widgets de ranking também precisam de um ID de ranking selecionado; consulte o status dos rankings.

Use a biblioteca do Cloud ​

Quando o host expuser capacidades de overlays do Cloud, abra a biblioteca em Sobreposições. Navegue por designs locais ou Meus overlays, use o editor para criar um overlay do Cloud ou abra um ID existente e revise-o. O editor do Cloud aceita texto, campos ao vivo, imagens e dimensões de tela; envios de imagens usam seu fluxo separado. Salvar o design local e criar/revisar no Cloud são operações distintas.

Resultado esperado e status ​

Designs locais, controles de gateway e fluxos do editor/biblioteca do Cloud condicionados às capacidades estão disponíveis. Um adaptador compartilhado Changes de overlays não está disponível nesta versão. OBS, LIVE real e cada sistema operacional ainda exigem aceitação no seu ambiente.

Recuperação ​

Para saída ausente, verifique estado do gateway, recursos, credenciais, URL da fonte e tipo de evento selecionado. Para um conflito de revisão no Cloud, recarregue a revisão atual antes de editar novamente. Nunca publique o token da fonte em capturas de tela; informe o erro do gateway pelos diagnósticos.

Da prévia para a transmissão

A demonstração permite explorar o design sem abrir o OBS. No seu computador, copie a URL com o controle da aplicação e valide um evento na fonte de navegador escolhida. A prévia local sozinha não confirma a entrega ao OBS.

Detalhes de operação ​

Instale Event Gateway separadamente, habilite e confira execução antes das fontes OBS LIVE. Estados: missing → instalar; disabled → habilitar/conferir disponibilidade; stopped → iniciar; credentialUnavailable → reiniciar gateway uma vez; assetsMissing → reparar/reconstruir assets empacotados; starting → aguardar brevemente; unreachable → conferir porta/serviço loopback. Use credencial de widget da URL gerada. Ready ou prévia local não provam LIVE nem recepção OBS: confira com teste inofensivo na fonte pretendida.
