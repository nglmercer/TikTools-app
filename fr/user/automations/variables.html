Réutiliser et examiner les variables d’exécution ​

Objectif et prérequis ​

Modifier une valeur partagée une seule fois et la réutiliser dans plusieurs actions. Il faut Automations → Variables et un hôte prenant en charge les opérations de variables concernées. L’édition typée et les opérations Cloud avec examen apparaissent selon les capacités de l’hôte ; enregistrer localement ne nécessite aucun téléversement.

Enregistrer une valeur locale ​

  1. Ajoutez une variable nommée showLabel. Les clés commencent par une lettre ou un trait de soulignement et peuvent contenir lettres, chiffres, points, traits de soulignement et traits d’union, jusqu’à 64 caractères. Évitez les doublons.
  2. Lorsque l’édition typée est disponible, choisissez le texte et saisissez Émission du soir. Les autres types pris en charge sont nombre, booléen, liste et secret. Les listes utilisent un tableau JSON de chaînes, tel que ["rouge", "bleu"].
  3. Sélectionnez Save. Un conflit de révision signifie que la collection enregistrée a changé ; rechargez-la et comparez votre modification prévue à celle-ci.
  4. Utilisez la valeur enregistrée dans un champ d’action acceptant les modèles :
text
{{ globals.showLabel }}: {{ event.user.uniqueId }}
  1. Testez une action limitée au journal pour examiner le texte rendu. Modifiez showLabel, enregistrez à nouveau et lancez un nouveau test. Les définitions d’action existantes peuvent réutiliser la valeur actualisée sans réimporter de modèle.

Les params du modèle sont substitués lors de son application ; les globals sont lues à l’exécution. Une clé d’exécution manquante produit un texte vide : vérifiez donc son orthographe avant de l’utiliser dans une destination ou un identifiant. Utilisez les suggestions de variables du champ pour choisir les chemins d’événement adaptés à son déclencheur.

Les conditions peuvent aussi publier des valeurs par correspondance. Lorsqu'un filtre déclare un alias de capture, la valeur qui l'a satisfait est disponible pendant le rendu des actions de l'événement sous la forme {{ match.<alias> }} (ou {{ match.<position> }} sans alias). Par exemple, une condition « commence par » sur le commentaire avec l'alias prefix permet à une action de journal d'afficher {{ match.prefix }}. Les captures sont du texte brut borné, ne sont produites que par les filtres et alternatives qui ont réellement correspondu, et ne modifient pas les clés de délai.

Appuyez sur + à côté d'un champ compatible avec les modèles pour ouvrir Insérer une variable : le chemin exact apparaît à droite et choisir une ligne ajoute {{ chemin }} au champ. Les captures de cet événement figurent aussi dans la liste, mais ne sont résolues que si leur condition a réellement correspondu. Déclarez un alias dans la section Conditions (le bouton Capturer du pied affiche les champs d'alias) pour écrire {{ match.<alias> }} ; sinon, utilisez la position {{ match.<position> }}.

Examiner séparément les changements Cloud ​

La commande Changes de Variables dispose d’opérations natives avec examen d’envoi, récupération, application/adoption et retrait lorsqu’elles sont prises en charge. Enregistrez d’abord les modifications locales, sélectionnez une comparaison, examinez son type et sa valeur, puis choisissez explicitement la direction voulue. Récupérer une proposition Cloud est distinct de son application locale. Retirer une valeur partagée est distinct de la suppression d’une ligne locale.

Les valeurs secrètes ou bloquées sont masquées dans les comparaisons et ne peuvent pas être envoyées par ce parcours avec examen. Ne transformez jamais un secret en texte ordinaire pour contourner ce blocage.

Résultat attendu, état et récupération ​

Les variables locales et le partage avec examen conditionné aux capacités sont disponibles ; enregistrer localement ne téléverse jamais automatiquement. Les clés invalides, valeurs typées invalides et révisions obsolètes bloquent l’enregistrement. Corrigez le champ signalé ou rechargez avant de réessayer. Pour les erreurs de compte, consultez le compte Cloud ; pour les comparaisons, consultez Changes.

Opérations en ligne de commande ​

Chaque opération de ce guide est aussi disponible depuis la CLI — hors ligne, scriptable et adaptée aux agents. Les lignes d'usage sont la syntaxe du parseur et restent en anglais dans toutes les langues.

CommandeRésumé
tiktools globals listlister toutes les clés globales
tiktools globals get <key>lire une globale
tiktools globals set <key> <value>écrire une globale
tiktools globals delete <key>supprimer une globale destructif

Consultez la référence complète des commandes pour les conventions, la sortie JSON et les marqueurs d’opérations destructives.
