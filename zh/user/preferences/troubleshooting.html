诊断失败的操作 ​

目标与前置条件 ​

定位故障组件，收集有用报告，并避免反复触发效果。你需要应用版本、故障大致时间及尝试的操作。重置或替换数据前，请保留备份。

查看最直接的证据 ​

  1. 阅读故障位置的行内错误。使用其诊断状态操作，或打开 诊断 查看相关条目。
  2. 按来源、级别或文本筛选。有用的来源包括 LIVE、监控、插件、账户、同步、更新、传输、目录、安装与协作。
  3. 选择相关条目，保留时间、代码、请求/实体标识符及简短说明。有详情时展开查看。
  4. 复制筛选后的诊断信息或导出文本报告。剪贴板/导出失败时，使用显示的备用文本。分享前检查并移除私有令牌、Cookie、邀请链接及个人内容。
  5. 提供简短复现步骤：页面、所选主播/配置/插件、执行操作、预期结果和实际结果。说明发生在更新前还是更新后。

隔离常见故障 ​

事件流为空时，清除搜索与筛选、恢复滚动并确认连接。暂停滚动不等于断线。显示丢失提示不能证明积分或统计也丢失了同一事件。

自动化没有运行记录时，检查当前配置、事件/操作启用状态、触发器、筛选字段路径及冷却时间。改变效果前先查看运行历史。运行测试 可能执行音频、HTTP、积分及插件操作。

插件故障请阅读安装作业或连接错误。Cloud 故障请检查账户状态及受影响区域，不要更换 TikTok Cookie。叠加层请检查网关状态和源配置。更新无法安装时，请使用手动更新指南。

预期结果与状态 ​

诊断筛选、复制及文本导出均可使用。打包应用还需要其 Web 资源和平台运行时。Linux 上检查受支持的 GTK/WebKitGTK 环境及 X11/XWayland 会话；Windows 上检查 WebView2。安装范围见系统要求。

恢复方法 ​

修正具体原因后再重试。修订冲突时，重新加载并审查当前保存状态。远程命令未确认时，先检查日志/状态再发送另一个命令：超时也可能发生在效果已成功之后。启动失败时，报告安装包、版本及启动日志，不要直接删除数据目录。

运行细节 ​

Diagnostics 是内存中的界面日志，上限为 2,000 条或 2 MiB；五秒内的重复项会合并。界面初始显示 100 条，导出包含所有匹配筛选的条目，而清空会删除整个日志。关闭、重启、清空或切换/退出已知 Cloud 账户前，请先复制或导出证据；这些账户切换会清空该界面历史。

窗口无法打开时，查看原生日志 tiktools.log（控制器模式为 controller.log）：Windows 默认在 %LOCALAPPDATA%/TikTools/logs，Linux 在 ${XDG_DATA_HOME:-~/.local/share}/TikTools/logs。TIKTOOLS_HOME 改变根目录，TIKTOOLS_LOG_DIR 覆盖日志目录。日志初始化自身失败时文件可能不存在，请保留可获得的终端/启动错误。原生日志不保证具备界面脱敏，分享前务必人工检查。

命令行操作 ​

本指南中的每个操作也可通过 CLI 使用——离线、可编写脚本、适合代理。用法行是解析器语法,在所有语言中保持英文。

命令摘要
tiktools system info主机版本和运行时信息
tiktools system health组件健康报告
tiktools system snapshot用于调试的完整状态快照
tiktools system doctor诊断常见的设置问题
tiktools system request-input-access向桌面用户请求输入访问权限
tiktools system shutdown关闭运行中的主机 破坏性

查看完整命令参考了解约定、JSON 输出和破坏性操作标记。
