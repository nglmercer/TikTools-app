Diagnosticar una operación fallida ​

Objetivo y requisitos ​

Identifica el componente que falla y reúne un informe útil sin repetir efectos continuamente. Necesitas la versión, la hora aproximada y la operación intentada. Conserva una copia antes de reiniciar o sustituir datos.

Inspeccionar la evidencia cercana ​

  1. Lee el error mostrado donde ocurrió el fallo. Usa su acción de diagnóstico o abre Diagnostics para inspeccionar las entradas relacionadas.
  2. Filtra por origen, nivel o texto. Entre los orígenes útiles están LIVE, supervisión, plugins, cuenta, sincronización, actualizaciones, transporte, catálogo, instalación y colaboración.
  3. Selecciona la entrada pertinente y conserva hora, código, identificadores de solicitud/entidad y descripción breve. Despliega los detalles disponibles.
  4. Copia los diagnósticos filtrados o exporta el informe de texto. Si falla el portapapeles o la exportación, utiliza el texto alternativo mostrado. Revísalo antes de compartir y elimina tokens, cookies, enlaces de invitación y contenido privado.
  5. Incluye una reproducción breve: página, creador/perfil/plugin seleccionado, acción, resultado esperado y resultado real. Indica si ocurrió antes o después de actualizar.

Aislar fallos comunes ​

Si el feed está vacío, borra búsqueda y filtros, reanuda el desplazamiento y confirma la conexión. Pausar la vista no desconecta. Un aviso de pérdida visual no demuestra que puntos o estadísticas perdieran el mismo evento.

Si no se ejecuta una automatización, comprueba perfil activo, interruptores de evento/acción, disparador, rutas de campos y espera. Inspecciona el historial antes de modificar efectos. Test puede ejecutar audio, HTTP, puntos y acciones de plugins.

Para plugins, lee el error del trabajo de instalación o de conexión. Para Cloud, revisa la sesión y el área afectada en lugar de cambiar una cookie de TikTok. Para superposiciones, inspecciona pasarela y fuente. Para actualizaciones, consulta la vía manual cuando no se pueda instalar.

Resultado esperado y estado ​

Están disponibles filtros, copia y exportación de diagnósticos. Un paquete también requiere sus recursos web y el entorno de plataforma. En Linux, verifica GTK/WebKitGTK y una sesión X11/XWayland compatible; en Windows, WebView2. Consulta el alcance de requisitos.

Recuperación ​

Repite después de corregir la causa concreta. Ante conflictos de revisión, carga y revisa el estado guardado actual. Si una orden remota queda sin confirmar, inspecciona su historial/estado antes de enviarla otra vez: el efecto puede haberse producido pese al tiempo de espera. Si falla el inicio, informa de paquete, versión y registro; evita borrar el directorio de datos.

Detalles de operación ​

Diagnostics es un registro UI en memoria, limitado a 2.000 entradas o 2 MiB. Agrupa repeticiones dentro de cinco segundos. Muestra inicialmente 100; exportar incluye todas las entradas filtradas, mientras Limpiar borra el registro entero. Copia/exporta antes de cerrar, reiniciar, limpiar o cambiar/cerrar una cuenta Cloud conocida: esos cambios vacían este historial.

Si no aparece ventana, revisa tiktools.log nativo (controller.log en modo controlador) en %LOCALAPPDATA%/TikTools/logs en Windows o ${XDG_DATA_HOME:-~/.local/share}/TikTools/logs en Linux. TIKTOOLS_HOME cambia la raíz y TIKTOOLS_LOG_DIR sustituye el directorio de logs. Si falla el propio registro, puede no existir archivo; conserva el error de terminal/inicio disponible. Los logs nativos no garantizan la redacción de la UI: revisa todo antes de compartir.

Operaciones de línea de comandos ​

Cada operación de esta guía también está disponible desde la CLI: sin conexión, scriptable y apta para agentes. Las líneas de uso son sintaxis del parser y permanecen en inglés en todos los idiomas.

ComandoResumen
tiktools system infoversión del host e información del runtime
tiktools system healthinforme de salud de los componentes
tiktools system snapshotinstantánea completa del estado para depuración
tiktools system doctordiagnosticar problemas comunes de configuración
tiktools system request-input-accesspedir acceso de entrada al usuario del escritorio
tiktools system shutdownapagar el host en ejecución destructivo

Consulta la referencia completa de comandos para las convenciones, la salida JSON y los marcadores de operaciones destructivas.
