Organizar automatizaciones ​

Objetivo y requisitos ​

Construye una biblioteca pequeña y comprensible que responda a eventos LIVE. Necesitas el host de escritorio funcionando. Una conexión LIVE real permite validar eventos externos; las acciones de plugins también requieren su plugin y servicio preparados.

Comprender la biblioteca ​

Una Action es una operación reutilizable configurada, como escribir una línea o reproducir sonido. Un Event elige disparador, filtros, espera y acciones vinculadas. Un perfil agrupa definiciones para un flujo de trabajo; solo hay un paquete de perfil activo a la vez. Las Variables proporcionan valores reutilizables por varias acciones.

  1. Abre Automations y confirma el perfil activo antes de editar. Busca Eventos y Acciones por separado para saber qué tipo de registro seleccionas.
  2. Comienza con la primera regla de registro. Crea la acción y después el evento que la referencia.
  3. Elige un disparador admitido por el host. Añade filtros mediante el selector de campos correspondiente. Varias condiciones restringen la coincidencia; no modifican el contenido entrante.
  4. Define el tiempo de espera y su ámbito. Una espera global limita la regla entre todos los espectadores; una espera por usuario los controla por separado.
  5. Vincula las acciones deseadas en orden. El modo normal ejecuta la lista elegida; el aleatorio selecciona una acción. Una acción de demora pospone las posteriores sin frenar la recepción LIVE.
  6. Guarda, revisa los cambios de definición que se muestren y activa explícitamente los registros deseados. Consulta el historial para comprobar nombre, resultado y error.

Toda comparación admite una lista de valores en lugar de un solo valor. La combinación predeterminada es «cualquiera»: la condición se cumple cuando al menos un valor coincide. Cambia el cuantificador a «todos» cuando todos los valores deban coincidir; con «no es» equivale a «no es ninguno». Una condición también puede nombrar un alias de captura: el valor ganador queda disponible para las plantillas de acción como {{ match.<alias> }} (o {{ match.<posición> }} sin alias). Debajo de las condiciones siempre obligatorias puedes añadir hasta cuatro alternativas: grupos cuyas condiciones deben cumplirse todas dentro del grupo, y basta con que un solo grupo se cumpla para que el evento se dispare.

Las pruebas pueden ejecutar los efectos configurados. Lee la lista seleccionada antes de pulsar Test o disparar un evento, especialmente si incluye audio, HTTP, puntos o plugins. Aprende primero con registros.

Resultado esperado y estado ​

Están disponibles la edición local, la ejecución, las plantillas, los perfiles y el historial. Los disparadores de plugins aparecen mientras su plugin está instalado y activo. La activación depende de la superficie y de los valores enabled revisados; comprueba eventos y acciones antes de confirmar. Changes en Eventos/Acciones es una comparación local, sin subida automática a Cloud.

Recuperación ​

Si no se ejecuta, comprueba perfil activo, interruptores, disparador, filtros, espera y acciones ausentes, en ese orden. Ante un conflicto de revisión, vuelve a leer la definición guardada y revísala. Evita sobrescribir a ciegas cambios ajenos. Exporta un perfil conocido antes de modificaciones amplias.

Detalles de operación ​

Antes de cambiar perfil/importar, lee activación por superficie. El cambio puede activar miembros deshabilitados individualmente. El cooldown vive en memoria, con máximo 24 horas; sin uniqueId los espectadores comparten ámbito anónimo. La tabla se vacía al alcanzar 8.192 claves: sobrecarga o reinicio pueden permitir ejecuciones adicionales. No es cuota durable ni garantía de replay.

Operaciones de línea de comandos ​

Cada operación de esta guía también está disponible desde la CLI: sin conexión, scriptable y apta para agentes. Las líneas de uso son sintaxis del parser y permanecen en inglés en todos los idiomas.

ComandoResumen
tiktools automation list [--kind event&#124;action&#124;all]listar las reglas de automatización
tiktools automation context [--event-type t]contexto de plantilla disponible para las reglas
tiktools automation get <id> [--kind event&#124;action]leer una regla
tiktools automation create --record json [--kind event&#124;action]crear una regla
tiktools automation update <id> --record json [--kind event&#124;action]actualizar una regla
tiktools automation delete <id> [--kind event&#124;action]eliminar una regla destructivo
tiktools automation enable <id> [--kind event&#124;action]activar una regla
tiktools automation disable <id> [--kind event&#124;action]desactivar una regla
tiktools automation test (--id <id> &#124; --record json) [--kind event&#124;action] [--trigger t] [--event json]probar una regla en seco contra un evento de muestra
tiktools automation fire --trigger <type> [--event json] [--record json]disparar un trigger manualmente
tiktools automation moderation-penalty --points <delta>aplicar una penalización de moderación en puntos
ComandoResumen
tiktools workflow listlistar los grafos de workflow guardados
tiktools workflow get <id>leer un grafo
tiktools workflow save --record jsoncrear o reemplazar un grafo
tiktools workflow delete <id>eliminar un grafo destructivo
tiktools workflow enable <id>activar un grafo
tiktools workflow disable <id>desactivar un grafo
