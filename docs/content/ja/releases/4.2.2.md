# TikTools 4.2.2 {#tiktools-422}

## 目的・公開状況・前提条件 {#goal-publication-status-and-prerequisites}

実装済み変数変更と残るリリース条件を確認します。2026年11月13日の状況は、**アプリのコンパイルと CI は成功、Linux インストーラーの梱包と Windows 梱包も成功しましたが、XKB 実行時依存の不足で AppImage 起動条件を満たせず、4.2.2 は未公開**です。インストーラーの公開成功、アップロード後のチェックサム検証、更新フィードの昇格は主張しません。

ビルド先は `hernan-lc/TikTools-app`、予定公開先は `RELEASE_REPO=nglmercer/TikTools-app` です。既存の4.2.1候補アセットは別です。入手可能なテスト版には[公開済み RC3](4.2.1-rc.3.md) を使い、実際のダウンロードは[リリース一覧](https://github.com/nglmercer/TikTools-app/releases) を確認します。

Cloud と共同操作の機能は実験段階です。ソース・候補テストには別途ビルドした対応ホスト、分離プロファイル、保存済みの秘密でない変数、現在の Cloud セッション・同意、通知されたネイティブ橋渡しが必要です。[開発環境](../developer/setup.md) を参照します。

## 実装された変数の変更 {#implemented-variables-changes}

変数は共有変更パネルを使います。送信は選択した保存済みネイティブ値だけを扱い、ダウンロードはキャッシュだけを更新します。確認した Cloud 値の適用と Cloud コピーの取り下げは別操作です。取り下げてもローカル値と秘密の分類は残ります。未保存下書きは先に保存か破棄し、橋渡しのない古いホストでは操作を隠します。

ホストは正確なセッション、同意、ローカルリビジョン、比較対象を検査します。待機中編集は置換・取消できます。エポックで防護した復旧は、結果不明のアップロードや秘密化後の取り下げで以前の値を再送しません。確認応答後に判断世代を進めます。未選択の変数や他セクションの待機列は送信対象外です。

大きな整数はブラウザー編集と比較・採用を通してネイティブの正確な文字列を保持します。別の変数を保存しても未編集の整数表現を保ちます。型はテキスト、数値、真偽値、リスト、ローカルシークレットです。秘密・禁止値には値の差分、送信、採用操作はありません。このアダプターにフィールド結合、強制、履歴、自動同期の操作はありません。

## 確認手順と期待結果 {#review-steps-and-expected-result}

1. 分離した対応候補で `demoGreeting = "こんにちは"` など無害な文字列を保存します。保存だけならローカルに留まるはずです。
2. ホストが対応を通知したら変数 → 変更を開きます。保存済みのローカル・Cloud 比較を確認し、目的の行だけを送信に選びます。
3. ダウンロードはキャッシュ更新として扱います。ローカル値の変更には別途確認して適用します。
4. Cloud コピーは明示的に取り下げます。ローカル値と秘密分類は維持されるはずです。
5. セッション、同意、リビジョン、対象が変わったら比較を更新して再確認します。結果不明なら新規アップロードを繰り返さず既存の復旧経路で解決します。

これらはソースから期待する動作で、新たに実行した本番受け入れ結果ではありません。

## CI の修正・復旧・未完了作業 {#ci-corrections-recovery-and-unfinished-work}

ソースはテストモジュール順序、ライフサイクルのフィクスチャーのプレリリース SemVer 許可、テストサーバーの上限付き完全ヘッダー読み取りを修正します。本番のプラグイン互換方針は変えません。リリース処理は分離プロファイルでの Linux AppImage 起動、内容検査、不変アップロード、取得し直したチェックサム、署名フィード公開を要求します。[復旧実行](https://github.com/hernan-lc/TikTools-app/actions/runs/43469055839) は、入れ子の linuxdeploy の後始末が親の展開先を消さないようにして Linux インストーラーを生成しました。次の検査は extract-and-run なのに FUSE インストール分類を要求する誤りがありました。復旧ツールは展開起動とマウント済みインストールを区別するようになりましたが、ネイティブ更新機能は引き続き展開配置を拒否します。[1回だけ許可された再実行](https://github.com/hernan-lc/TikTools-app/actions/runs/43484544700) は梱包と2つの CLI 検査に成功し、libxkbcommon-x11 を読めず frontend-ready 前に失敗しました。公開できない処理へ時間を費やさないよう残りはキャンセルされました。修正は XKB パッケージを導入し、動的読み込みライブラリと依存を同梱します。ローカル Ubuntu の読み込み検査は成功しました。修正版 AppImage の完全な起動と公開は未検証で、追加の Actions は開始していません。

梱包復旧と検証済み公開が終わるまで公開アセットを使い、[更新ガイド](../user/updates.md) に従います。プロファイルをバックアップしてください。バイナリ置換では DB 移行は戻りません。変数の失敗では保留状態、版、秘密除去済みの要求・エラー詳細を保持し、[診断](../user/preferences/troubleshooting.md) を使います。

チームのニックネーム探索と宛先固定招待には引き続きバックエンド `6a69c99` と移行 `20261113000001_remote_invitation_recipients.sql` が必要です。このアプリビルドはバックエンドを配置しません。自動化の Cloud 通信、オーバーレイリビジョン、履歴・ブランチの出所、残る共同操作の表示作業は別です。過去の LIVE SQLite ロック保持者は未特定です。ローカル・偽アカウント検査ではサインイン済み本番同期やチーム互換性は確認できません。
