# TikTools 4.2.1-rc.3 {#tiktools-421-rc3}

## 目的・公開状況・前提条件 {#goal-release-status-and-prerequisites}

2026年11月13日の報告では RC3 は公開済みプレリリースです。バックアップと別のテストプロファイルを用意し、RC2 後の Linux デスクトップ変更を評価します。安定チャンネルの更新ではなく候補版です。[リリース一覧](https://github.com/nglmercer/TikTools-app/releases) から公開 AppImage、DEB、可搬型アセットと `SHA256SUMS.txt` を取得します。記録されたパッケージはローカルで作成されました。

Cloud セクションの復旧と共同操作は実験段階です。インストールではバックエンド移行を配置せず、本番アカウントの互換性も証明しません。

## RC3 で利用できる変更 {#changes-available-in-rc3}

- RC2 の並行比較読み取り修正と、ネイティブ失敗理由を示すローカル再試行を維持します。
- 変数はテキスト、数値、真偽値、リスト、ローカルシークレットを永続化します。原子的保存はホスト変更や古い編集リビジョンを拒否し、既存のテンプレート文字列描画を保ちます。
- 秘密はマスクされたままです。ホスト切替で旧書き込みへ戻ることはなく、ネイティブ分類は秘密になる前に待機列へ入った値も後の公開・比較から除外します。
- ネイティブ変数橋渡しはキャッシュ比較、1変数の明示採用、キャッシュだけの取得に対応します。アプリはセッション、同意、ローカルリビジョン、キャッシュ項目を再検査します。

変数の保存はローカルのままです。RC3 は確認付き送信・取り下げと保留競合処理を備える完全な変数変更ボタンを公開しません。その統合は [4.2.2 のソースノート](4.2.2.md) にあります。ローカル値を秘密にしても以前公開した Cloud コピーは消えません。

## 公開候補を確認する {#check-the-published-candidate}

1. チェックサムと表示 `4.2.1-rc.3` を確認します。テストプロファイルと XDG ディレクトリを通常環境から分離します。
2. `demoGreeting = "こんにちは"` など無害なテキスト変数を作り、保存・再読込します。他の明示的な型も機密性のない値で確認します。
3. 変更の読み込み・ローカル再試行を試します。設定/チームと任意のガイドを確認し、バックエンド機能不足を設定成功と扱いません。
4. 失敗は正確な操作、版、ネイティブ理由、要求 ID を報告します。トークン、招待コード、秘密値を含めません。

## 期待される結果・証拠・復旧 {#expected-result-evidence-and-recovery}

型付きローカル値は再読込後も残り、古いホスト・リビジョンの編集は明確に失敗するはずです。原記録はネイティブ変数・同期・整合性検査、偽ホストのブラウザーテスト、分離 CLI 検証、インストーラー内容、空の分離プロファイルでの frontend-ready 起動を報告します。サインイン済み本番同期やメディア再生の証拠ではありません。

AppImage の記録 SHA-256 は `4b11260836457350debf2680b230c52cea8408ddf17ccdc729d0025a62149b7e` です。取得物の添付チェックサムを確認します。失敗時はコピーしたプロファイルを保ち、復旧を再試行する前に[トラブルシューティング](../user/preferences/troubleshooting.md) を使います。

ニックネーム招待にはバックエンド `6a69c99` と移行 `20261113000001_remote_invitation_recipients.sql` が必要です。旧記録では人物ルート不足が観測されましたが、ここで新しい本番検査を行ったとは主張しません。自動化の Cloud 通信、オーバーレイリビジョン、残りの共同操作監査は未完了で、過去の SQLite ロック保持者も不明でした。
