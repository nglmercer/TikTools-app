# TikTools 4.2.1-rc.2 {#tiktools-421-rc2}

## 目的・状況・前提条件 {#goal-status-and-prerequisites}

RC2 の過去の記録から、RC1 で再現した変更の並行読み取りの修正を理解します。Actions 無効中にローカルでビルドした Linux AppImage、DEB、可搬型パッケージが対象です。現在の取得可否や新規 Windows パッケージは確認しません。[リリース一覧](https://github.com/nglmercer/TikTools-app/releases) から選び、チェックサムを保管して分離プロファイルで試します。

Cloud 復旧と共同操作は実験段階です。ニックネーム検索には引き続きバックエンド `6a69c99` と移行 `20261113000001_remote_invitation_recipients.sql` が必要で、アプリのパッケージはそれらを配置しません。

## 修正と期待される動作 {#correction-and-expected-behavior}

変更・競合一覧とプロトコル選択は、製品の変更スロットを予約せずプロトコル観測を共有します。無関係のパッケージジャーナルがスロットを使用中でも、ツールバー・パネルの読み取りを完了できます。書き込みの防護、アカウント分離、明示的移行判断は維持します。

アカウント検査はログアウト、遷移保留、置換セッションを拒否します。ローカル比較の読み取りで認証情報を復元したり Cloud 要求を開始したりしません。失敗時はネイティブの理由とローカル再読込を表示します。この再試行は送信、取得、レコード解決を行いません。

## 候補を確認する {#check-the-candidate}

1. 表示 `4.2.1-rc.2` を記録し、分離プロファイルでプラグイン → 変更を開きます。
2. ツールバーとパネルから比較を開くか再読み込みします。失敗時は「すべて同期済み」とせず理由を保持するはずです。
3. ローカル再試行が、保留列の変更やリモートレコード適用なしで比較を再読込することを確認します。
4. アカウント・セッション遷移を別に記録します。影響プロファイルの再現では [RC1 の移行手順](4.2.1-rc.1.md) と比べます。

## 記録済み検証と復旧 {#recorded-validation-and-recovery}

原記録には決定的な32読み取りの回帰、CloudAuth・同期・ネイティブ・フロントエンドの検査、空の分離プロファイルでの最適化 AppImage 起動が記載されています。インストーラー内容と可搬アーカイブも確認されました。その起動ではサインイン済み本番同期やメディア再生は試していません。

記録された AppImage の SHA-256 は `35fc26e7bc5875c5a3fe99bf6a84baf77af8ca63d1c8b8e61825881187d6091f` です。そのファイルを識別する値であり、実際の取得物には添付チェックサムを使います。

読み込みが失敗する場合は版、ネイティブエラー、要求 ID を保持して[診断](../user/preferences/troubleshooting.md) を使います。保留編集と競合を保全します。RC2 でも自動化はローカル基準、変数とオーバーレイは未完了、過去の SQLite ロック保持者は不明でした。古いバックエンドに欠けていた人物検索ルートがその後配置されたとは主張しません。
