# 効果音と読み上げを設定する {#set-up-sounds-and-speech}

## 目的と前提条件 {#goal-and-prerequisites}

混雑した LIVE に音声を連動させる前に、予測できる音を再生します。正常な出力機器と対応する既存音声ファイルが必要です。ローカルの **サウンドを再生** (`audio.play`) は組み込みアクションです。SonicBoom などの読み上げ連携には専用プラグイン・サービスの設定が必要です。

## ローカル音声を試す {#test-a-local-sound}

1. **自動化 → アクション** で **サウンドを再生** (`audio.play`) を作り、メディア選択で既存ファイルを指定します。
2. 最初は音量 `0.2` にします。範囲は `0`～`1` で、ゼロは無音です。
3. 重複時の方針を選びます。`allow` は同時再生、`restart` は最初から再生、`drop` は再生中の新しい要求を無視します。
4. 保存して設定を読み、**テストを実行** を選びます。このテストでは実際に音が鳴ることがあります。
5. 目的の機器で聞きます。ローカル再生が成功してから、控えめな[フィルターとクールダウン](../automations/recipes.md) を持つイベントに関連付けます。

アクションはパスに基づくメディア参照を保持し、音声ファイルを DB にコピーしません。ファイルをそのパスに保ち、移行やバックアップでは別途含めてください。

## 任意の読み上げ機能を設定する {#configure-optional-speech}

信頼できる読み上げプラグインを [プラグイン](index.md) からインストールします。接続・設定でサービスアドレス、認証、プロバイダー、言語、音声・プロファイルを確認します。音声カタログを読み込んでから、機密性のない短文をテストします。音声がない場合は架空の ID で代用せず、カタログ、所有権、プロバイダーの不一致を調べます。

SonicBoom では合成、再生受付、聞こえるまでの完了は別の結果です。待機列への追加や開始応答だけでは、人が聞けたことは確認できません。クローン音声はチャットの到着より遅い場合があるため、待機列・飽和の診断を確認し、イベント受付数を制限します。

## 期待される結果・提供状況と対処 {#expected-result-status-and-recovery}

ホストが音声対応を通知していればローカル再生を利用できます。読み上げはインストール済みプラグインと接続可能なサービスに依存し、各プロバイダー・機器・プラットフォームでの動作は保証されません。無音ならファイル、音量、出力機器、一時停止、実行エラーを確認します。読み上げ失敗ではサービスと音声カタログを調べてから再試行します。配信中の繰り返しテストを避け、[診断](../preferences/troubleshooting.md) ではトークンや読み上げた非公開文を共有しないでください。
