# プラグインをインストール・管理する {#install-and-manage-plugins}

## 目的と前提条件 {#goal-and-prerequisites}

連携を追加し、要求アクセスを確認してアクションが使えることを確かめます。プラグインの OS、アーキテクチャ、ホストバージョンに対応するデスクトップパッケージが必要です。リモートカタログとダウンロードにはネットワークが、一部のアカウント方式サービスには [Cloud サインイン](../cloud/account.md) も必要です。

## 有効化前に確認する {#review-before-enabling}

1. **プラグイン** のインストール済み、探す、アップデートを確認します。探すはプラグイン項目だけを取得します。自動化テンプレートとプロファイルは [自動化](../automations/templates.md) にあります。
2. 説明、バージョン、互換性、ランタイムを確認します。見慣れた表示名だけを信じず、発行者と要求機能・権限を確認します。
3. インストール画面でパッケージをプレビューし、確定前に正確なバージョン、署名、要求アクセス、既存版からの変更を読みます。
4. ジョブ結果を待ちます。ダウンロード、インストール、有効化は別段階で、カタログカードだけでは実行準備は完了していません。
5. プラグインの設定または接続を開き、専用欄だけにアドレスと認証情報を入力します。提供されていれば宣言済みの接続確認を使います。
6. 有効化後、アクション種別やページの表示を確認します。強力な外部アクションを結び付ける前に、範囲を絞った[ログ記録ルール](../automations/first-rule.md) を作ります。

プラグインはネイティブコードや別プロセスを実行できます。プロセス分離はクラッシュを切り離せても OS のサンドボックスではありません。信頼できる発行者のソフトウェアを使います。有効な署名は確認された出所を示しますが、すべての処理が用途に適するとは限りません。

## 期待される結果と提供状況 {#expected-result-and-status}

パッケージ確認、インストールジョブ、設定、バージョン管理を利用できます。実際のアクションはマニフェスト、ホスト機能、外部サービスに依存します。イベントプロセッサーには専用パネルがあり、イベントに任意の分析フィールドを追加できます。生のフィールドとは区別されます。

## 問題が起きたとき {#recovery}

失敗時はジョブのエラーから互換性、署名、ランタイム、取得の問題を読みます。エラーを消すために検証を弱めないでください。更新後の問題では保持版を確認し、可能ならロールバックします。無効化・削除前に依存する自動化を確認し、プラグインのデータと設定を[バックアップ](../preferences/backups.md) します。
