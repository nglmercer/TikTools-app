# 実行時変数の再利用と変更の確認 {#reuse-and-review-runtime-variables}

## 目的と前提条件 {#goal-and-prerequisites}

共有値を一度変更し、複数のアクションで再利用します。**自動化 → 変数** と、対象の変数操作に対応するホストが必要です。型付き編集や確認を伴う Cloud 操作はホスト機能に応じて表示されます。ローカル保存にアップロードは不要です。

## ローカル値を保存する {#save-a-local-value}

1. `showLabel` という変数を追加します。キーは英字かアンダースコアで始め、英数字、ドット、アンダースコア、ハイフンを含められます。上限は `64` 文字です。キーの重複を避けます。
2. 型付き編集が利用できる場合、テキストを選び `夜の配信` と入力します。他に数値、真偽値、リスト、シークレットを利用できます。リストは `["赤", "青"]` などの文字列の JSON 配列です。
3. **グローバル変数を保存** を選びます。リビジョン競合は保存済みコレクションが変わったことを意味するため、再読み込みして変更内容を照合します。
4. テンプレート対応のアクション欄で保存値を使います。

```text
{{ globals.showLabel }}: {{ event.user.uniqueId }}
```

5. ログだけのアクションをテストして展開後のテキストを確認します。`showLabel` を変更して保存し、もう一度テストします。テンプレートを再インポートしなくても既存アクションは更新された値を使えます。

テンプレートの `params` は適用時に置換され、`globals` は実行時に読まれます。存在しない実行時キーは空文字になるため、送信先や識別子で使う前に綴りを確認してください。イベントのパスは各フィールドの変数候補からトリガーに合うものを選びます。

## Cloud の変更は別途確認する {#review-cloud-changes-separately}

変数の **変更** では、対応ホスト上で送信、取得、適用・採用、取り下げを確認付きで実行できます。先にローカル編集を保存し、比較を選び、型と値を確認して方向を明示的に選びます。Cloud 候補の取得とローカル適用は別操作です。共有値の取り下げとローカル行の削除も異なります。

シークレットや送信禁止の値は比較でマスクされ、この経路では送信できません。制限を回避するためにシークレットを通常テキストに変えないでください。

## 期待される結果・提供状況と対処 {#expected-result-status-and-recovery}

ローカル変数と、ホスト機能に応じた確認付き共有を利用できます。ローカル保存で自動アップロードは行われません。不正なキー、型に合わない値、古いリビジョンでは保存できません。強調された欄を修正するか、再読み込みしてから再試行します。アカウントの問題は [Cloud アカウント](../cloud/account.md)、比較の動作は [変更](../cloud/changes.md) を参照してください。
