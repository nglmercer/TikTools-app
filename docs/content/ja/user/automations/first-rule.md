# 最初のログ記録ルールを作る {#create-your-first-logging-rule}

## 目的と前提条件 {#goal-and-prerequisites}

チャットイベントから、読みやすいローカルログを1行出力します。デスクトップホストが起動し、**自動化** を開ける必要があります。Cloud アカウント、音声サービス、外部エンドポイントは不要です。

<DocCallout title="最初はローカルのログで結果を確認する" tone="tip">

最初のルールをログ記録だけに限定すると、結果を確認しやすくなります。ログには展開後のメッセージが記録されるため、架空の内容か機密性のないチャットを使ってください。操作例には、リセットできるサンプル環境が用意されています。

</DocCallout>

## アクションを作る {#create-the-action}

<DocSteps>

1. **編集画面を開きます。** 使用するプロファイルで **自動化 → アクション** を開きます。
2. **アクションに名前を付けます。** **メッセージをログに記録** (`core.log`) のアクションを作り、`チャット確認` と名付けます。
3. **メッセージを設定します。** **メッセージ** 欄に次のテンプレートを入力し、保存してアクションを有効にします。

</DocSteps>

```text
チャット確認: {{ event.user.uniqueId }} の発言: {{ event.data.comment }}
```

`event.data.comment` は正規化済みのチャット本文、`event.user.uniqueId` は視聴者のハンドルです。表示名には別のフィールドを使います。

## イベントを作る {#create-the-event}

<DocSteps>

1. **トリガーを選びます。** **イベント** を開き、`チャット確認イベント` を作成して `tiktok.chat` を選びます。
2. **アクションを関連付けます。** `チャット確認` だけを追加し、通常の全アクション実行モードを維持します。
3. **基準となる動作を確認します。** 最初のサンプルテストではフィルターを空にします。後で実際の通信量を制限できるよう、全体のクールダウンを `10` 秒にします。
4. **結果をテストします。** 保存し、変更のプレビューが表示されたら確認します。ログのアクションだけが関連付けられた状態で **テストを実行** を選び、返された実行結果とログを確認します。ホストが提供するサンプルで成功しても、TikTok への実接続の確認にはなりません。
5. **条件を絞ります。** `event.data.comment` に、等しい (`eq`)、値 `!こんにちは` の条件を追加します。再保存し、イベントを明示的に有効にします。
6. **実際のチャットを確認します。** テストを許可された [LIVE](../live/connections.md) に接続します。[フィード](../live/feed.md) で新しい `!こんにちは` のチャットを確認し、クールダウン経過後に自動化の履歴を調べます。

</DocSteps>

## 期待される結果と提供状況 {#expected-result-and-status}

ローカルのログアクションとチャットトリガーを利用できます。サンプルでは読めるログが出力されます。条件に合う実際のチャットでは、実際のハンドルとメッセージを含む実行結果が得られ、それ以外のチャットは完全一致の条件を通過しないはずです。

<DocCallout title="イベントから実行結果までを確認する" tone="info">

アクティブなプロファイル、アクションとイベントの有効状態、メッセージの一致、クールダウンの経過を確認してください。フィードにチャットが表示されただけでは、自動化が実行されたとは限りません。

</DocCallout>

## 問題が起きたとき {#recovery}

フィルター追加後にサンプルが一致しなくなった場合、サンプルのコメントが `!こんにちは` と異なる可能性があります。繰り返し実行せず、実イベントのフィールド、アクティブなプロファイル、有効状態を確認します。テストでも実際の処理が動くため、ログだけに限定すると影響を予測できます。終了時にイベントを無効にするか、[実用例](recipes.md) に進んでください。
