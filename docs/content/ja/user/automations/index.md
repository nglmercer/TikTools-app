# 自動化を整理する {#organize-automations}

## 目的と前提条件 {#goal-and-prerequisites}

LIVE のイベントに反応する、小さく分かりやすいライブラリを作ります。正常に動くデスクトップホストが必要です。配信元のイベントの検証には実際の [LIVE 接続](../live/connections.md) が、プラグインのアクションには対応するプラグインとサービスの準備も必要です。

## ライブラリの仕組み {#understand-the-library}

**アクション** はログ出力や音の再生など、設定を再利用できる処理です。**イベント** はトリガー、フィルター、クールダウン、関連アクションを指定します。プロファイルは用途ごとに定義をまとめ、一度に有効になるプロファイルパックは1つです。実行時の[変数](variables.md) を使うと、複数のアクションで値を共有できます。

1. **自動化** を開き、編集前にアクティブなプロファイルを確認します。イベントとアクションは別々に検索し、選ぶレコードの種類を把握します。
2. [最初のログ記録ルール](first-rule.md) から始めます。先にアクションを作り、それを参照するイベントを作成します。
3. 現在のホストが対応するトリガーを選び、フィールド選択から対応するフィルターを追加します。複数条件は一致範囲を絞りますが、受信ペイロードは変更しません。
4. クールダウンと適用範囲を設定します。全体のクールダウンは全視聴者を通じてルールを制限し、ユーザー別では視聴者ごとに管理します。
5. 目的のアクションを順に関連付けます。通常モードは選んだ一覧を実行し、ランダムモードはその中から1つ選びます。遅延アクションは後続処理を遅らせますが、LIVE の取り込みは遅らせません。
6. 保存して表示された定義の変更を確認し、実行するレコードを明示的に有効にします。履歴でアクション名、結果、エラーを確認します。

テストでも設定した処理が実行されます。特に音声、HTTP、ポイント、プラグインでは、**テストを実行** やイベント実行の前に選択中のアクション一覧を読んでください。学習中はログを使います。

## 期待される結果と提供状況 {#expected-result-and-status}

ローカル編集、実行、テンプレート、プロファイル、履歴を利用できます。プラグインのトリガーは対応プラグインがインストールされ有効な間だけ表示されます。インポートした定義は明示的に有効化するまで無効です。イベント／アクションの **変更** は[ローカルの基準との比較](../cloud/changes.md) であり、Cloud への自動アップロードではありません。

## 問題が起きたとき {#recovery}

実行されない場合は、アクティブなプロファイル、有効状態、トリガー、フィルター、クールダウン、欠けたアクションの順に確認します。リビジョンが競合したら、現在の保存済み定義を読み直して再確認します。他の人の更新を無条件に上書きしないでください。大きな変更の前に、正常な[プロファイル](templates.md) をエクスポートします。
