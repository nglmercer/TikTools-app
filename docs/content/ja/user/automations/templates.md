# テンプレートのインポートとプロファイルの管理 {#import-templates-and-manage-profiles}

## 目的と前提条件 {#goal-and-prerequisites}

確認済みのルールやルール集を、誤って実行せずに再利用します。**自動化**、信頼できる JSON ファイルまたはカタログ項目、アクションが必要とするプラグインを用意します。既存の構成を置き換える前に、現在のプロファイルをエクスポートしてください。

## 適切な操作画面を選ぶ {#choose-the-right-surface}

`.tiktemplate.json` は1つのイベントとそのアクションを記述し、`.tikprofile.json` は複数のテンプレートをまとめます。組み込み・カスタムテンプレート、Cloud ライブラリ、手動テンプレートインポートは自動化のテンプレートダイアログで開きます。プロファイルの作成、選択、エクスポート、手動インポートはプロファイルツールバーを使います。**プラグイン → 探す** はプラグインを探す画面で、テンプレートとプロファイルはこちらで扱います。

## 確認してインポートする {#review-and-import}

1. 対象のインポートダイアログを開き、ファイルを選ぶか、対応する JSON を貼り付けます。続行前に準備された名前と出所を確認します。
2. テンプレートではトリガー、アクション種別、パラメーターを確認します。プロファイルでは項目数と共通パラメーターも確認します。
3. 例の送信先、メディアパス、視聴者識別子を自分の構成に合う値に置き換えます。共有用ファイルに認証情報を貼り付けないでください。
4. 適用・インポートを明示的に実行して結果を待ちます。定義は無効のまま取り込まれます。後で選択し、各アクションとイベントを確認して必要なものだけを明示的に有効化します。
5. まずログだけのテストをするか、定義を確認します。HTTP、音声、ポイント、プラグインのテストでは実際の処理が動きます。
6. LIVE 開始前にアクティブなプロファイルを確認します。切り替えは選択中のライブラリの対象を変更する操作であり、Cloud 同期の命令ではありません。

<code v-pre>{{ params.giftName }}</code> などのパラメーターはテンプレート適用時に解決されます。<code v-pre>{{ event.user.uniqueId }}</code> などの実行時参照は各イベントのために残り、[グローバル変数](variables.md) は実行時に保存済みの共有値を提供します。

## 期待される結果と提供状況 {#expected-result-and-status}

ローカルのテンプレート・プロファイルの入出力を利用できます。Cloud の閲覧には対応するホスト機能とアカウント・サービスが必要です。カタログのプレビューだけでは外部サービスの動作は確認できません。必要なプラグインがなければ、インストールと設定が済むまで取り込んだ定義を使えない場合があります。

## 問題が起きたとき {#recovery}

無効な JSON はパーサーのエラーと期待される文書形式を確認します。任意の JSON の名前を変えても形式は変換されません。リビジョン競合では保存済みライブラリを更新してから再適用します。正常なプロファイルの書き出しを保持し、含まれないデータについては[バックアップ](../preferences/backups.md) を参照してください。
