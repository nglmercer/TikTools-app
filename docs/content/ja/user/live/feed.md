# LIVE フィードを読む・調べる {#read-and-inspect-the-live-feed}

## 目的と前提条件 {#goal-and-prerequisites}

イベントとフィールドを調べ、表示の一時停止とルームの切断を区別します。[LIVE 接続](connections.md) を用意するか、現在のフィード内のイベントを使います。フィードは件数に限りがある作業用表示で、配信全体の記録ではありません。

## 動きを確認する {#inspect-activity}

1. **ライブフィード** を開き、接続状態で現在の配信者を確認します。
2. 全イベント、チャット、ギフト、いいね、フォロー、入室、その他の交流からフィルターを選びます。検索と組み合わせ、投稿者、メッセージ、ギフト名、正確なギフト ID を探します。
3. **自動スクロールを一時停止** で自動スクロールを止めて読みます。受信は継続し、未読数が増えることがあります。TikTok の切断や自動化の停止は行いません。
4. イベントを選びインスペクターを開きます。自動化用のフィールドを選ぶ前に種別と詳細を確認します。すべてのイベントにチャット、ギフト情報、視聴者 ID があるわけではありません。
5. 視聴者名かアバターで追跡プロフィールを開きます。詳細パネルが隠れていればインスペクターの切り替えを使います。
6. **自動スクロールを再開** または未読へのジャンプで新着へ戻ります。受信の有無を確認する際は検索を消し、全イベントを選びます。

可能な場合はラベル付き操作にキーボードでフォーカスして使います。動きで読みにくい場合はスクロール停止が役立ちます。アバターがなくてもイニシャルが表示され、画像がなくても視聴者を識別できます。

## 期待される結果と提供状況 {#expected-result-and-status}

フィルターと詳細確認を利用できます。大量受信時は表示範囲が制限され、UI イベントの欠落が報告されることがあります。これは表示の指標なので、見えている行数を集計値にしないでください。[分析](../points/statistics.md) は永続化済み集計を別に照会します。

## 問題が起きたとき {#recovery}

空ならフィルターを外し、スクロールを再開して接続状態を確認します。静かなルームでも正常な場合があります。同じ配信者への再接続は対象を保持し、切り替えると対象が変わります。**フィードを消去** は作業用フィードだけを消し、ポイントや統計はリセットしません。欠落表示は[診断](../preferences/troubleshooting.md) で調べ、表示にない行がすべて配信元でも失われたとは判断しないでください。
