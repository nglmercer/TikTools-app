# Cloud アカウントにサインインする {#sign-in-to-your-cloud-account}

## 目的と前提条件 {#goal-and-prerequisites}

デスクトップアプリを設定済み Cloud サービスに接続し、アカウントを使うカタログや共同操作を利用します。ネットワーク、システムブラウザー、正常な OS の認証情報ストアが必要です。Cloud なしでもローカル編集は使えます。Cloud セッションは TikTok LIVE の認証にはなりません。

## サインインして本人情報を確認する {#sign-in-and-verify-identity}

1. **設定 → アカウント** を開き、別のログインを始める前に現在の状態を確認します。
2. **ログイン** を選びます。デスクトップがローカルのコールバック受信口を起動し、設定済みログインページをシステムブラウザーで開きます。
3. サービスのログインを完了して TikTools に戻ります。ブラウザーが開かない場合は、その試行用に表示されたログイン URL を使います。この URL は非公開にし、公に投稿しないでください。
4. サインイン済みになるまで待ち、非公開カタログやチームを開く前に表示名かメールアドレスを確認します。
5. エラーが出たらアカウントの診断詳細を開きます。未完了の試行は **キャンセル** で終了し、複数を同時に残さないでください。
6. 共有 PC で使い終えたら **ログアウト** を選び、アカウント状態が変わったことを確認します。

ネイティブホストがセッショントークンを扱い、OS の認証情報ストアに保存します。フロントエンドには秘密を含まない状態だけを保持します。安全な保存先が使えない場合に平文ファイルへ代替保存することはありません。データフォルダーをコピーしても、サインイン済みセッションは移せません。

## 期待される結果と提供状況 {#expected-result-and-status}

Cloud 認証付きでビルドされたホストでは、ネイティブのサインイン、復元、サインアウトを利用できます。設定済みアカウントは再起動時に復元し、サービスで再検証できます。未設定・非対応のホストは TikTok Cookie を変更しても直りません。

ログインサービスの利用可否と実際のプロバイダー・プラットフォームでの動作は、配置されたサービスと端末に依存します。ローカル検証だけでは、本番の全ログイン経路の動作は証明できません。

## 問題が起きたとき {#recovery}

キャンセル・期限切れなら古い試行を閉じてから新しく始めます。ネットワークやサービスのエラーでは診断コードを保持し、復旧後に再試行します。認証情報ストアのエラーでは OS の安全な保存機能を復旧してください。Bearer トークンを設定やサポートメッセージへ貼り付けないでください。明示的な同期は [変更](changes.md)、別途付与するアクセス権は[共同操作](collaboration.md) を参照します。

## 運用の詳細 {#operational-details}

ログアウトは先にローカル資格情報・アカウント文脈を消し、サーバー失効を最善努力で試します。ログアウト表示はローカル削除を示し、通信失敗時の遠隔 token 失効は保証しません。サービスにセッション管理があれば利用します。既知アカウントの変更・終了前に Diagnostics を書き出します。その UI 履歴は消去されます。TikTok Cookie・遠隔ホストセッションは別 ID です。
