# 領域ごとに変更を確認する {#review-changes-by-area}

## 目的と前提条件 {#goal-and-prerequisites}

リセット、送信、採用の前に **変更** が何を比較するか把握します。保存済みのローカル内容が必要です。Cloud 操作には対応ホスト、適切な同期モード、[サインイン済みアカウント](account.md) も必要です。同じ名前のパネルでも通信の動作は異なります。

## イベントとアクションをローカルで確認する {#review-events-and-actions-locally}

1. **自動化** を開き、イベントまたはアクションを選んで **変更** を開きます。
2. 注意書きを読みます。ここでは現在の定義と端末内に保持した基準を比較します。最初に読み込んだときに基準を作るため、変更が表示されなくても正常です。
3. 追加・変更・削除されたレコードを選び、変更前後の値を確認します。
4. 現在のセクションを新しいローカル基準にする場合だけ **確認済みにする** を選びます。定義のアップロードや委任された実行の承認は行いません。
5. 基準の状態に戻したい場合だけ **同期済みのバージョンに戻す** を使います。新規レコードは削除され、変更・削除済みレコードは保持した定義に戻ります。必要なら先に書き出します。

この版のイベント／アクションアダプターには、個々の定義用の Cloud コレクションがありません。差分がなくても、Cloud バックアップや別の PC への反映を意味しません。

## 変数とプラグインを明示的に確認する {#review-variables-and-plugins-explicitly}

変数は独自のネイティブ共有を備えています。ローカル保存後、候補を取得して比較し、送信、適用・採用、取り下げを明示的に選びます。シークレットや禁止値はマスクされたままで、この経路から送信できません。ローカル保存ではアップロードしません。[変数](../automations/variables.md) を参照してください。

プラグインの変更は対応する同期ワークスペースで、選択プラグインと準備済み設定を扱います。公開単位は各行ではなくセクションです。設定では値を出さず変更されたキー名を示します。競合時はローカル版か Cloud 版を選び、任意のフィールド結合は行いません。公開前にセクションの操作と選択された同期モードを確認します。

Cloud オーバーレイは[ライブラリ・エディター](../overlays/index.md) の作成・改訂フローを使います。この基本版には共有オーバーレイ用変更アダプターがありません。

## 期待される結果・提供状況と対処 {#expected-result-status-and-recovery}

ローカルの自動化比較と、ホスト機能に応じたネイティブ共有をそれぞれの領域で利用できます。リモートに影響する操作はサービスに依存し、本番動作の確認を意味しません。確認内容が古くなったら更新して再比較します。結果が未確認なら、新しい操作を作る前に状態・ジャーナルを確認してください。タイムアウトは「何も変わらなかった」証拠ではありません。
