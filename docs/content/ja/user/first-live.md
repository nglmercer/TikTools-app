# 最初の LIVE 接続 {#first-live-connection}

## 目的と前提条件 {#goal-and-prerequisites}

自動化を有効にする前に、1人の配信者からイベントを受け取ります。正常なデスクトップ環境、ネットワーク、現在配信中の配信者が必要です。Cloud サインインは別の接続で、TikTok を認証しません。

## 接続する {#connect}

1. **接続**、または下部ステータスバーの **接続** を開きます。
2. 配信者のハンドルを入力します。先頭の `@` は省略できます。表示名を使わず綴りを確認します。
3. ゲスト接続できる場合は **セッションCookieを使用** を無効にして始めます。許可された自分のセッションが必要なルームでは有効にし、専用のマスク欄だけに Cookie を入力します。
4. 最初の直接接続では監視を無効のままにし、**接続** を押して状態が確定するまで待ちます。
5. **ライブフィード** を開き、問題のないチャットを依頼するか実イベントを待ちます。配信者と時刻を確認します。
6. イベントを選んで詳細を確認します。視聴者名かアバターを選ぶと追跡中のプロフィールを確認できます。

## 期待される結果 {#expected-result}

接続済みになり、受信イベントがフィードに表示されます。静かなルームでは新規イベントがないことも正常です。ポイントは有効なポイントルール、自動化の結果は設定したアクションとイベントに依存します。

## 監視と再接続 {#monitoring-and-reconnecting}

直接接続に成功した後、**監視して自動接続** で配信開始を待てます。状態には待機、確認中、接続処理が区別されます。固定された配信者欄を編集するには監視を停止します。同じ配信者への再接続では現在のフィードを保持し、配信者を変えると別のフィード対象になります。

## 問題が起きたとき {#recovery}

オフラインなら配信中か確認してから再試行します。認証・レート制限のエラーでは **診断** を読み、示された再試行条件に従います。連打しても期限切れの配信元セッションは直りません。Cookie が必要なら新しい許可済みセッションを取得し、値を画像、ログ、問い合わせに含めないでください。Cookie はメモリーに保持され、Cloud 用の再利用可能な認証情報ではありません。

別の配信者を試す前に切断します。デモは架空のイベントで操作を学ぶためのもので、成功しても TikTok セッションの検証にはなりません。
