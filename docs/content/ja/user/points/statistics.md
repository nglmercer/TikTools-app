# 日付を指定して統計を確認する {#review-statistics-across-dates}

## 目的と前提条件 {#goal-and-prerequisites}

配信者の活動を必要な期間で比較し、表示フィードやポイント残高と合計が違う理由を理解します。この環境に活動が記録され、[接続](../live/connections.md) で目的の配信者が選択されている必要があります。Cloud サインインはローカル統計のデータ源ではありません。

## 記録済み期間を照会する {#query-the-recorded-period}

1. **分析** を開き、日付欄の横の配信者を確認します。選択した配信者によって照会する保存済み集計が決まります。
2. **今日**、`7d`、`30d`、`90d`、または任意期間を選びます。任意の日付は開始・終了を明示し、前後関係を確認します。
3. 比較前に表示期間とセッション数を読みます。ローカル日付の境界はタイムゾーン差を使い、PC のタイムゾーンを変えると期間の解釈も変わる場合があります。
4. チャット、ギフト、いいね、ダイヤモンド、最大視聴者数から指標を選びます。活動グラフで期間を比較し、貢献者表で返された上位視聴者を確認します。
5. 貢献者検索は返されたデータに含まれる視聴者が対象です。過去の全視聴者を無制限に検索する機能ではありません。
6. 新しい活動の後やページに戻った際は **更新** を選びます。数値の共有時は配信者、日付、指標も記録します。

現在のページは配信者と日付範囲でネイティブの `analytics.summary` を呼びます。過去のセッションを含む永続化済み集計を読み、現在のフィード内に残るイベントには限定されません。統計 DB は集計を保存し、チャット全文は保存しません。

## 期待される結果と提供状況 {#expected-result-and-status}

永続化されたローカル統計と期間照会を利用できます。記録のない日付で活動が返らないのは正常です。ポイントは[付与率](rules.md)、手動調整、自動化の付与による別の測定なので、残高と一致しない場合があります。ダイヤモンド、ギフト数、ポイントは置き換え可能な単位ではありません。

## 問題が起きたとき {#recovery}

データがなければ貢献者検索を消し、期間を広げ、配信者を確認して更新します。ホストエラーでは診断コードを保持し、接続復旧後に再試行します。フィード消去で統計は消えません。新規データディレクトリに過去履歴はないため、環境移行では[バックアップ](../preferences/backups.md) を使います。

## 運用の詳細 {#operational-details}

Analytics は選択した配信者と日付範囲の上位貢献者を現在 10 人取得します。検索対象は受信した部分集合で、全視聴者検索ではありません。永続集計の期間・単位は、フィードのセッション内ダイヤ・いいねランキングやポイント残高とは異なります。書き出しや比較では配信者・日付・指標も残してください。
