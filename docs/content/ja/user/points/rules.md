# ポイントルールを設定する {#configure-point-rules}

## 目的と前提条件 {#goal-and-prerequisites}

受信した活動に対するローカル通貨の付与方法を選び、単純な付与を1つ確認します。TikTools を起動し、後の LIVE 確認に使う配信者を決めておきます。ポイントルールと自動化アクションは独立しており、自動化を作らなくてもルールで付与できます。

<DocCallout title="獲得元を1つずつ試す" tone="tip">

最初はチャット1件につき1ポイントだけを設定します。残高の変化を確認してから、ギフト、いいね、サブスクライバーのボーナスを追加しましょう。これはアプリ内のローカルポイントで、TikTok 通貨や支払いの約束ではありません。

</DocCallout>

## 獲得方針を設定する {#set-the-earning-policy}

<DocSteps>

1. **通貨に名前を付けます。** **ポイント** の **ポイントルール** を開き、**通貨名** を `スター` など分かりやすい名前に設定します。
2. **獲得元を選びます。** ギフトのコイン、チャットメッセージ、いいね、シェア、フォロー、入室には、それぞれ率と有効スイッチがあります。最初は **チャットメッセージ** の `1` ポイントだけを有効にし、他を無効にします。基準を確認する間は **サブスクライバーのボーナス** を `0` にします。
3. **レベルの進み方を設定します。** **レベルごとのポイント** を例えば `100` にします。編集画面の最小値は `10` で、率は負にできません。
4. **設定を保存します。** **ルールを保存** を選び、確認を待ちます。編集中の **破棄** は保存済み設定に戻します。

</DocSteps>

<DemoFrame scenario="points" locale="ja" panel="points" title="ポイントルールと視聴者の残高を操作する" />

[接続](../live/connections.md) で接続し、[フィード](../live/feed.md) の新規チャットを確認してから、**リーダーボードを更新** を選び、該当視聴者を検索します。

ギフトといいねの率は受信した貢献量を使います。例えば `10` いいね、1件当たり `0.1` ポイントなら、特典適用前に `1` ポイントです。表示の1行が貢献1単位とは限りません。率の変更は以後の付与方針を変え、過去を再計算しません。

## 期待される結果と提供状況 {#expected-result-and-status}

ローカルルール、残高、手動の加算・減算を利用できます。チャットだけの構成では、受け付けた新規チャット1件につき視聴者残高が1増えます。レベルは設定した1レベル当たりのポイントに従います。

<DocCallout title="変更後の残高を比較する" tone="info">

自動化でもポイントを付与すると二重になる場合があります。チャット1件の想定より多く増える場合は、有効な獲得元と自動化を確認してください。

</DocCallout>

## 問題が起きたとき {#recovery}

最初に獲得元のスイッチ、保存済み率、視聴者識別子を確認します。LIVE 接続が有効または処理中の間はリセットがロックされます。計画したリセットの前に切断し、確認内容を読みます。累積残高を消す前に[アプリを閉じてバックアップ](../preferences/backups.md) してください。

## 運用の詳細 {#operational-details}

<DocCallout title="リセットの範囲を確認する" tone="warning">

行メニューのリセットは1人のポイントを `0`、レベルを `1` にし、リセット記録を追加します。**すべてのポイントをリセット** は配信者に関係なく、このインストールに保存された全視聴者の残高を `0`、レベルを `1` にし、ポイント取引履歴を削除します。視聴者レコードと累積カウンターは残り、フィードと分析は消しません。LIVE を切断し、アプリを閉じてバックアップしてから範囲を確認してください。

</DocCallout>

手動の加算にも保存済みサブスクライバーのボーナスが適用されます。50% の場合、サブスクライバーへの +100 は +150 になります。−100 の減算には加算ボーナスを適用せず、残高は 0 未満になりません。入力した差分だけで判断せず、結果の残高を確認してください。表の検索は取得済み上位 100 人だけが対象で、見つからなくても保存レコードがないとは限りません。
