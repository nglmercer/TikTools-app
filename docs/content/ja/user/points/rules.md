# ポイントルールを設定する {#configure-point-rules}

## 目的と前提条件 {#goal-and-prerequisites}

受信した活動に対するローカル通貨の付与方法を選び、単純な付与を1つ確認します。TikTools を起動し、後の LIVE 確認に使う配信者を決めておきます。ポイントルールと自動化アクションは独立しており、自動化を作らなくてもルールで付与できます。

## 獲得方針を設定する {#set-the-earning-policy}

1. **ポイント** のルールパネルを開き、`スター` など分かりやすい通貨名を設定します。
2. ギフトのコイン、チャット、いいね、シェア、フォロー、入室から必要なソースだけを有効にします。各ソースに率と有効スイッチがあります。
3. 最初はチャット `1` ポイントだけを有効にし、他を無効にします。基準を確かめる間はサブスク特典を `0` にします。
4. 1レベル当たりを例えば `100` ポイントに設定します。編集画面の最小値は `10`、率は負にできません。
5. **ルールを保存** を選び、確認を待ちます。編集中の **破棄** は保存済み設定に戻します。
6. [接続](../live/connections.md) で接続し、[フィード](../live/feed.md) の新規チャットを確認してから、順位表を更新して該当視聴者を検索します。

ギフトといいねの率は受信した貢献量を使います。例えば `10` いいね、1件当たり `0.1` ポイントなら、特典適用前に `1` ポイントです。表示の1行が貢献1単位とは限りません。率の変更は以後の付与方針を変え、過去を再計算しません。

## 期待される結果と提供状況 {#expected-result-and-status}

ローカルルール、残高、手動の加算・減算を利用できます。チャットだけの構成では、受け付けた新規チャット1件につき視聴者残高が1増えます。レベルは設定した1レベル当たりのポイントに従います。これはアプリ内のローカルポイントで、TikTok 通貨や支払いの約束ではありません。

## 問題が起きたとき {#recovery}

最初にソースのスイッチ、保存済み率、視聴者識別子を確認します。自動化でも付与すると二重になる場合があります。LIVE 接続が有効または処理中の間はリセットがロックされます。計画したリセットの前に切断し、確認内容を読みます。累積残高を消す前に[アプリを閉じてバックアップ](../preferences/backups.md) してください。
