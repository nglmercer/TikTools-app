# TikTools 4.2.1-rc.1

## Objetivo, estado y requisitos

Usa este registro histórico para reproducir los problemas de recuperación Cloud, Teams y AppImage Linux investigados en RC1. Describe la aplicación `338495a9` y, por separado, el backend `6a69c99`. Estas notas no acreditan la disponibilidad actual de descargas RC1. Revisa los [artefactos publicados](https://github.com/nglmercer/TikTools-app/releases) antes de elegir un instalador.

El candidato registrado utilizó AppImage, DEB y paquetes portátiles Linux compilados localmente mientras Actions estaba deshabilitado. No incluyó un instalador Windows recién compilado. Conserva una copia de seguridad y un perfil aislado para probar la migración. La colaboración y la recuperación Cloud por sección siguen siendo experimentales.

## Cambios del candidato

- Settings conserva cuenta, sesión y diagnósticos; Plugins reúne catálogo, búsqueda, Changes e instalación. Las plantillas y perfiles permanecen en Automations.
- El panel Changes distingue un fallo de comparación de un resultado vacío correcto. La sección Plugins envía sus selecciones y ajustes, conservando las demás colas y las descargas en caché.
- La migración admite que falte el directorio implícito de plugins incluidos, mantiene estrictas las rutas explícitas e identifica los paquetes ausentes para una reparación revisada. Conserva ediciones pendientes y conflictos.
- Teams diferencia registrar este PC como host de seleccionar el host de otro equipo. Las invitaciones por apodo quedan ligadas al destinatario elegido y siguen requiriendo aprobación del host.
- La ayuda opcional sigue el estado de configuración. El empaquetado Linux incluye helpers WebKit, plugins GStreamer y su scanner para comprobar después la reproducción.

## Reproducir y comprobar el resultado esperado

1. Anota la versión mostrada y el sistema operativo. Abre Plugins → Changes y conserva el error exacto y el identificador de petición si falla la carga.
2. En el perfil copiado, previsualiza la migración y revisa los IDs exactos antes de reparar paquetes ausentes. Repite la vista previa; las ediciones pendientes y los conflictos deben conservarse.
3. En Teams, registra el PC actual antes de probar Start. Seleccionar el host de otro equipo no debe autorizar el arranque de este.
4. Comprueba por separado el inicio del AppImage y el audio/vídeo. Llegar al frontend no acredita reproducción multimedia correcta.

La búsqueda por apodo y las invitaciones ligadas al destinatario requieren el backend `6a69c99` y la migración `20261113000001_remote_invitation_recipients.sql`. Instalar este candidato no despliega ese backend.

## Recuperación y límites de la evidencia

Si falla una comparación, conserva el motivo nativo y reintenta mediante el panel admitido. No elimines el estado pendiente ni deduzcas una migración correcta de una comprobación de compatibilidad. Recoge versión, acción y diagnósticos redactados según la [guía de solución de problemas](../user/preferences/troubleshooting.md).

El registro original informa de pruebas de frontend, sincronización, aislamiento de destinatarios y dos hosts nativos/relay en su revisión. Son resultados fechados, no una validación nueva de producción. No se identificó al responsable del bloqueo SQLite histórico. En RC1 faltaban los adaptadores Cloud de Variables y Overlays, y Automations comparaba una referencia local. Consulta las [notas posteriores](4.2.1-rc.3.md) y la [guía actual de Changes](../user/cloud/changes.md).
