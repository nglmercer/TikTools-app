# TikTools 4.2.1-rc.3 {#tiktools-421-rc3}

## Objetivo, estado de publicación y requisitos {#goal-release-status-and-prerequisites}

RC3 es una versión preliminar publicada, según el estado comunicado el 13 de noviembre de 2026. Úsala para evaluar los cambios Linux posteriores a RC2, con una copia de seguridad y un perfil de pruebas separado. Es un candidato, no una actualización del canal estable. Descarga el AppImage, DEB o paquete portátil publicado y su `SHA256SUMS.txt` desde la [lista de versiones](https://github.com/nglmercer/TikTools-app/releases); los paquetes registrados se compilaron localmente.

La recuperación Cloud por sección y la colaboración siguen siendo experimentales. La instalación no despliega migraciones del backend ni acredita compatibilidad con cuentas de producción.

## Cambios disponibles en RC3 {#changes-available-in-rc3}

- Conserva la corrección RC2 de lecturas simultáneas y el reintento local con el motivo nativo.
- Variables guarda tipos text, number, boolean, list y secret local. El guardado atómico rechaza cambios de host o revisiones antiguas y conserva el renderizado de texto en plantillas existentes.
- Los secretos siguen enmascarados. Cambiar de host no permite recurrir a una escritura antigua; la clasificación nativa excluye valores encolados antes de convertirse en secretos del envío posterior y de la comparación.
- El puente nativo de Variables permite comparar caché, adoptar explícitamente una variable y descargar solo a caché. La aplicación vuelve a comprobar sesión, consentimiento, revisión local y entrada de caché.

Guardar Variables sigue siendo local. RC3 no expone el botón completo Changes de Variables con envío/retirada revisados y gestión de conflictos pendientes; esa integración se describe en las [notas del código 4.2.2](4.2.2.md). Marcar un valor local como secreto no borra una copia previamente publicada en Cloud.

## Comprobar el candidato publicado {#check-the-published-candidate}

1. Verifica el checksum del paquete y la versión mostrada `4.2.1-rc.3`. Separa el perfil de pruebas y los directorios XDG del perfil habitual.
2. Crea una variable de texto inocua, por ejemplo `demoGreeting = "Hello"`, guarda y recarga. Comprueba los demás tipos con valores de muestra sin datos sensibles.
3. Abre Changes y prueba carga y reintento local. Revisa Settings/Teams y la ayuda opcional sin interpretar capacidades ausentes del backend como configuración correcta.
4. Informa de acción exacta, versión, motivo nativo e identificador de petición. Excluye tokens, códigos de invitación y valores secretos.

## Resultado esperado, evidencia y recuperación {#expected-result-evidence-and-recovery}

Los valores locales tipados deben conservarse al recargar y los cambios con host o revisión obsoletos deben fallar visiblemente. El registro original informa de pruebas nativas de Variables/sync/paridad, navegador con host simulado, CLI aislada, contenido de instaladores e inicio frontend-ready con un perfil vacío. No demuestra sincronización autenticada de producción ni reproducción multimedia.

El SHA-256 registrado del AppImage es `4b11260836457350debf2680b230c52cea8408ddf17ccdc729d0025a62149b7e`; verifica el archivo de checksums de tu descarga. Si falla, conserva el perfil copiado y consulta [solución de problemas](../user/preferences/troubleshooting.md) antes de reintentar recuperaciones.

Las invitaciones por apodo dependen del backend `6a69c99` y la migración `20261113000001_remote_invitation_recipients.sql`. El registro antiguo observó la ausencia de la ruta de personas; aquí no se afirma una nueva comprobación de producción. Faltaban transporte Cloud de Automations, revisiones Overlay y parte de la auditoría de colaboración; el responsable del bloqueo SQLite histórico seguía sin conocerse.
