# 配置积分规则 {#configure-point-rules}

## 目标与前置条件 {#goal-and-prerequisites}

选择传入活动如何赚取本地虚拟货币，再验证一次简单奖励。你需要运行 TikTools，并确定之后用于直播检查的主播。积分规则与自动化操作相互独立：即使没有创建自动化，规则仍可发放积分。

<DocCallout title="每次只测试一种来源" tone="tip">

先只启用聊天，每条消息奖励一分。在加入礼物、点赞或订阅者加成前，这样更容易核对预期余额。这些是应用内本地积分，并非 TikTok 货币或兑付承诺。

</DocCallout>

## 设置获取规则 {#set-the-earning-policy}

<DocSteps>

1. **为货币命名。** 打开 **积分**，找到 **积分规则**，选择易识别的 **货币名称**，例如 `星星`。
2. **选择奖励来源。** 礼物金币、聊天消息、点赞、分享、关注和进入直播间各有独立的倍率和启用开关。首次检查只启用 **聊天消息**，每条 `1` 分，并将 **订阅者加成** 保持为 `0`。
3. **设置升级规则。** 设置 **每级所需积分**，例如 `100`。编辑器要求最少 `10`，倍率不得为负数。
4. **保存规则。** 选择 **保存规则** 并等待确认。编辑过程中，**丢弃** 会恢复已保存的配置。

</DocSteps>

<DemoFrame scenario="points" locale="zh" panel="points" title="试用积分规则与观众余额" />

通过[连接](../live/connections.md)连接，在[事件流](../live/feed.md)中观察新的聊天事件，再使用 **刷新排行榜** 并搜索该观众。

礼物和点赞倍率使用收到的贡献数量。例如，`10` 个点赞按每赞 `0.1` 分计算，在任何适用加成之前产生 `1` 分。显示的一行事件不一定等于一个贡献单位。修改倍率只设置后续奖励规则，不会重新计算过去的数据。

## 预期结果与状态 {#expected-result-and-status}

本地规则、观众余额及手动增减控件均可使用。仅启用聊天的测试中，每个被接受的新聊天应让该观众余额增加一分。等级按配置的每级所需积分计算。

<DocCallout title="核对最终余额" tone="info">

如果自动化也发放积分，可能产生第二次奖励。观众所得积分超过单独聊天的一分奖励时，请检查已启用的来源和当前自动化。

</DocCallout>

## 恢复方法 {#recovery}

先检查来源开关、已保存倍率及观众标识符。直播连接活动或忙碌时，重置控件会锁定。计划重置前，请断开连接并阅读确认提示。清除累计余额前，进行[关闭应用后的备份](../preferences/backups.md)。

## 运行细节 {#operational-details}

<DocCallout title="确认重置范围" tone="warning">

行菜单只将一位观众的积分归零、等级设为 1，并添加重置标记。**重置所有积分** 影响本安装中所有已保存的观众，不按主播划分：所有余额归零、等级设为 1，并删除积分交易历史。观众记录及累计计数仍保留；它不会清空事件流或数据分析。先断开直播，在应用关闭时备份，再核对范围并确认。

</DocCallout>

手动增加积分也应用已保存的订阅者加成：加成为 50% 时，给订阅者增加 100 实际得到 150。扣除 100 不应用该加成，余额最低为零。请核对最终余额，不要假定输入的增减值就是实际变化。表格搜索仅覆盖当前前 100 名快照；未找到观众不代表没有保存记录。
