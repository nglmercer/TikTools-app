# TikTools 4.2.1-rc.3 预发行版 {#tiktools-421-rc3}

## 目标、发布状态与前置条件 {#goal-release-status-and-prerequisites}

根据 2026 年 11 月 13 日报告，RC3 是已发布的预发行版。使用备份和独立测试配置，评估 RC2 之后的 Linux 桌面变化。它是候选版，并非稳定通道更新。从[发布列表](https://github.com/nglmercer/TikTools-app/releases)下载已发布的 AppImage、DEB 或便携资源及其 `SHA256SUMS.txt`；记录中的包由本地构建。

Cloud 分区恢复和协作仍属实验性。安装不会部署后端迁移，也不能证明生产账户兼容。

## RC3 中可用的变化 {#changes-available-in-rc3}

- 保留 RC2 对并发比较读取的修正，以及带原生失败原因的本地重试。
- 变量持久化文本、数字、布尔、列表和本地秘密类型。原子保存拒绝已变化的宿主或过期编辑器修订，同时保留既有模板文本渲染。
- 秘密值保持遮蔽。切换宿主不能回退到旧写入路径；原生分类会将变为秘密之前已排队的值排除在后续发布和比较输出之外。
- 原生变量桥支持缓存比较、明确采纳单个变量和仅更新缓存的下载。应用时重新检查会话、同意、本地修订及缓存条目。

保存变量仍在本地进行。RC3 不提供包含审查式发送/撤回及待处理冲突处理的完整变量更改按钮；该分区集成见 [4.2.2 源码说明](4.2.2.md)。将本地值标记为秘密，不会擦除先前发布的 Cloud 副本。

## 检查已发布候选版 {#check-the-published-candidate}

1. 验证包校验和及显示的 `4.2.1-rc.3` 版本。将测试配置和 XDG 目录与日常配置分开。
2. 创建无害文本变量，例如 `demoGreeting = "你好"`，保存后重新加载。使用不敏感样例值检查其他明确类型。
3. 打开更改，测试加载和本地重试。检查设置/团队及可选引导帮助，不要将缺少后端能力视为设置成功。
4. 失败时报告确切操作、版本、原生原因和请求 ID。报告中不要包含令牌、邀请码或秘密值。

## 预期结果、证据与恢复 {#expected-result-evidence-and-recovery}

类型化本地值应在重新加载后保留，宿主或修订过期的编辑应明确失败。原始记录报告了原生变量/同步/对等检查、模拟宿主浏览器测试、沙箱 CLI 验证、安装器内容检查，以及空隔离配置下到达 frontend-ready 的启动。它不能证明已登录的生产同步或媒体播放正常。

记录中的 AppImage SHA-256 为 `4b11260836457350debf2680b230c52cea8408ddf17ccdc729d0025a62149b7e`；请验证实际下载附带的校验和文件。失败时保留复制配置，并在重试恢复操作前使用[故障排查](../user/preferences/troubleshooting.md)。

昵称邀请依赖后端 `6a69c99` 及迁移 `20261113000001_remote_invitation_recipients.sql`。旧记录观察到人员路由缺失；这里不声称执行了新的生产探测。自动化 Cloud 传输、叠加层修订及其余协作审计尚未完成，历史 SQLite 锁持有者仍未知。
