# TikTools 4.2.1-rc.2 候选版记录 {#tiktools-421-rc2}

## 目标、状态与前置条件 {#goal-status-and-prerequisites}

使用 RC2 历史说明了解针对 RC1 中复现的并发更改读取问题所做的修正。候选版记录涵盖 Actions 禁用期间本地构建的 Linux AppImage、DEB 和便携包，不能证明目前可下载，也不代表新构建了 Windows 包。请从[发布列表](https://github.com/nglmercer/TikTools-app/releases)选择资源，保留校验和文件，并使用隔离配置测试。

Cloud 恢复及协作仍属实验性。昵称搜索仍依赖后端 `6a69c99` 及迁移 `20261113000001_remote_invitation_recipients.sql`；应用包不会部署这些变更。

## 修正与预期行为 {#correction-and-expected-behavior}

更改/冲突列表及协议选择共享协议观察，不再占用产品修改槽位。无关包日志操作占用该槽位时，工具栏和面板读取仍可完成。写入屏障、账户隔离和明确的迁移决定保持不变。

账户检查拒绝退出登录、待处理转换和替换会话。读取本地比较不会恢复凭据或启动 Cloud 请求。失败时，UI 显示原生原因及本地重新加载操作；该重试不会发送、下载或解决记录。

## 检查候选版 {#check-the-candidate}

1. 记录显示的 `4.2.1-rc.2` 版本，在隔离配置中打开插件 → 更改。
2. 从工具栏和面板打开或重新加载比较。加载失败应保留原因，而非报告所有内容已同步。
3. 使用本地重试，确认它重新加载比较，而不改变待处理队列或应用远程记录。
4. 单独记录账户/会话转换。复现受影响配置时，对照 [RC1 迁移流程](4.2.1-rc.1.md)。

## 已记录的验证与恢复 {#recorded-validation-and-recovery}

原始记录描述了确定性的 32 读取者回归、CloudAuth/同步/原生/前端检查，以及优化后的 AppImage 在空隔离配置下启动。记录了安装器内容及便携归档检查。该启动没有测试已登录的生产同步或媒体播放。

历史 AppImage SHA-256 为 `35fc26e7bc5875c5a3fe99bf6a84baf77af8ca63d1c8b8e61825881187d6091f`。它只标识记录中的文件；请使用实际下载资源附带的校验和。

加载仍失败时，保留版本、原生错误和请求 ID，再使用[诊断](../user/preferences/troubleshooting.md)。保留待处理编辑和冲突。RC2 时，自动化仍使用本地参考，变量和叠加层分区尚未完成，历史 SQLite 锁持有者仍未识别。这些说明不声称旧后端缺失的人员搜索路由后来已经部署。
