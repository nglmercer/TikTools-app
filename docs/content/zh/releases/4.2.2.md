# TikTools 4.2.2 构建与恢复状态 {#tiktools-422}

## 目标、发布状态与前置条件 {#goal-publication-status-and-prerequisites}

本说明用于审查已实现的变量变化及发行版剩余门控。2026 年 11 月 13 日报告的状态：**应用编译和 CI 检查已通过；Linux 安装器现已成功打包，Windows 打包也通过，但 AppImage 启动门控因缺少 XKB 运行时依赖失败，4.2.2 尚未发布**。这里不声称安装器已成功发布、已验证上传后下载的校验和，或已提升更新源。

构建在 `hernan-lc/TikTools-app` 中运行，预期发布目标为 `RELEASE_REPO=nglmercer/TikTools-app`。现有 4.2.1 候选版资源仍独立存在。需要可用测试版时，使用[已发布 RC3 预发行版](4.2.1-rc.3.md)；实际可下载资源请查看[发布列表](https://github.com/nglmercer/TikTools-app/releases)。

这些 Cloud 和协作功能仍属实验性。源码/候选版测试需要独立构建的匹配宿主、隔离配置、已保存的非秘密变量、当前 Cloud 会话/同意，以及声明支持的原生桥。请参阅[开发环境设置](../developer/setup.md)。

## 已实现的变量变化 {#implemented-variables-changes}

变量使用共享更改面板。发送仅处理选中的已保存原生值；下载只刷新缓存。应用已审查 Cloud 值与撤回其 Cloud 副本是不同操作。撤回保留本地值及秘密分类。未保存的本地草稿必须先保存或放弃；没有原生桥的旧宿主会隐藏控件。

宿主检查确切会话、同意、本地修订及目标比较。排队编辑可替换或取消。带纪元屏障的恢复处理不确定上传，以及值变为秘密后的撤回，而不重放之前的值。确认后，决定代次向前推进。未选中的变量和其他分区队列不参与选定发送。

大整数在浏览器编辑及比较/采纳过程中保留精确原生文本。保存其他变量时，会保留未触碰整数的文本。类型仍包括文本、数字、布尔、列表和本地秘密。秘密或被阻止的值不提供值差异、发送或采纳控件。此适配器没有字段合并、强制、历史或自动同步控件。

## 审查步骤与预期结果 {#review-steps-and-expected-result}

1. 在匹配的隔离候选版中，保存无害文本值，例如 `demoGreeting = "你好"`。仅保存应保持在本地。
2. 宿主声明支持后，打开变量 → 更改。审查已保存的本地/Cloud 比较，仅为发送已保存的值选择预期行。
3. 将下载视为缓存更新。在期待本地值改变前，单独审查并在此设备上使用云端版本。
4. 使用明确撤回移除 Cloud 副本。本地值及其秘密分类应保持不变。
5. 会话、同意、修订或目标改变时，刷新比较并重新审查。通过现有恢复路径解决不确定结果，不要将上传作为新操作重复。

这些是源码预期行为，不是新执行的生产验收结果。

## CI 修正、恢复与未完成工作 {#ci-corrections-recovery-and-unfinished-work}

源码修正了测试模块顺序、生命周期夹具对预发行 SemVer 的明确允许，以及测试服务器有界的完整头部读取。生产插件兼容策略保持不变。发布流程要求 AppImage 在 Linux 隔离配置下启动、检查安装器内容、不可变上传、下载后校验和验证及签名更新源发布。[恢复运行](https://github.com/hernan-lc/TikTools-app/actions/runs/43469055839)阻止嵌套 linuxdeploy 清理删除父进程的解压目录后，生成了 Linux 安装器。下一项检查在使用解压运行时，错误要求 FUSE 安装分类。恢复工具现已区分解压启动与挂载安装；原生更新器仍拒绝解压布局。[唯一获授权的重跑](https://github.com/hernan-lc/TikTools-app/actions/runs/43484544700)通过打包及两项 CLI 探测，随后在 frontend-ready 之前因无法加载 libxkbcommon-x11 失败。剩余工作被取消，避免为已无法继续的发布消耗运行分钟。修复会安装 XKB 包，并将动态加载库及依赖一起打包；本地 Ubuntu 加载检查通过。完整修正后的 AppImage 启动和发布仍未经验证，没有再启动其他 Actions 运行。

打包恢复和验证发布完成前，请使用已发布资源，并遵循[更新指南](../user/updates.md)。保留配置备份；替换二进制文件不会撤销数据库迁移。变量故障请保留待处理状态、版本及脱敏请求/错误详情，并使用[诊断](../user/preferences/troubleshooting.md)。

团队昵称发现及绑定收件人的邀请，仍依赖后端 `6a69c99` 和迁移 `20261113000001_remote_invitation_recipients.sql`。此应用构建不会部署后端。自动化 Cloud 传输、叠加层修订、历史/分支来源及剩余协作展示工作是独立事项。历史直播 SQLite 锁持有者仍未识别。本地/假账户检查不能证明已登录的生产同步或团队兼容性。
