# TikTools 4.2.1-rc.1 候选版记录 {#tiktools-421-rc1}

## 目标、状态与前置条件 {#goal-status-and-prerequisites}

本篇历史候选版记录可用于复现 RC1 调查的 Cloud 恢复、团队和 Linux AppImage 问题。它描述应用基线 `338495a9` 及独立后端基线 `6a69c99`，不能证明 RC1 下载目前仍可用。选择安装器前，请检查[已发布资源](https://github.com/nglmercer/TikTools-app/releases)。

当时 Actions 被禁用，记录中的候选版使用本地构建的 Linux AppImage、DEB 和便携包，不含新构建的 Windows 安装器。迁移测试请保留备份，并隔离复制受影响配置。协作和 Cloud 分区恢复仍属实验性功能。

## 此候选版的变化 {#changes-in-this-candidate}

- 设置保留账户/会话及诊断；插件管理其目录、搜索、更改和安装操作。模板与配置仍位于自动化。
- 共享更改面板区分比较失败与成功的空结果。插件分区发送自己的选择/设置，同时保留其他队列及缓存下载。
- 迁移容忍缺少隐式内置插件目录，对明确配置的路径保持严格，并指出缺失包 ID 以供审查修复。待处理编辑和冲突均会保留。
- 团队区分将当前电脑注册为宿主与选择另一台电脑上的宿主。昵称邀请绑定选定收件人，仍需宿主批准。
- 可选引导帮助跟随设置状态。Linux 打包包含 WebKit 辅助程序、GStreamer 插件及扫描器，供后续媒体检查。

## 复现并检查预期结果 {#reproduce-and-inspect-the-expected-result}

1. 记录显示版本和操作系统。打开插件 → 更改，加载失败时保留确切错误及请求 ID。
2. 在复制的配置中预览迁移，修复前审查确切的缺失包 ID。之后再次预览；待处理编辑及冲突应仍然存在。
3. 在团队中，先注册当前电脑再测试开始控件。选择另一台电脑的宿主不应授权启动本机。
4. 先检查 AppImage 启动，再分别检查音频/视频。仅到达前端不能证明媒体播放成功。

昵称搜索和绑定收件人的邀请，需要后端 `6a69c99` 及迁移 `20261113000001_remote_invitation_recipients.sql`。安装此候选版不会部署该后端。

## 恢复与证据限制 {#recovery-and-evidence-limits}

比较失败时，保留原生原因，并通过受支持面板重试。不要删除待处理状态，也不要从兼容性检查推断迁移成功。按[故障排查指南](../user/preferences/troubleshooting.md)收集版本、操作及脱敏诊断详情。

原始记录报告了其基线上的前端、同步引擎、收件人隔离和双宿主原生/中继检查。这些有日期的检查不是最新生产验证。历史 SQLite 锁持有者未被识别。RC1 时，变量和叠加层 Cloud 适配器尚未完成，自动化比较本地参考。后续范围请阅读[后来的候选版说明](4.2.1-rc.3.md)及[当前变更指南](../user/cloud/changes.md)。
