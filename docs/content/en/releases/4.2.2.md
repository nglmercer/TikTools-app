No successful installer publication, uploaded checksum verification or update-feed promotion is claimed.

These Cloud and collaboration features remain experimental. Source/candidate testing requires a separately built matching host, an isolated profile, saved non-secret Variables, current Cloud session/consent and the advertised native bridge. See [development setup](../developer/setup.md).

## Implemented Variables changes

Variables uses the shared Changes panel. Send handles only selected saved native values; download refreshes only the cache. Applying a reviewed Cloud value and withdrawing its Cloud copy are separate actions. Withdrawal retains the local value and secret classification. Unsaved local drafts must be saved or discarded first, and older hosts without the bridge hide the control.

The host checks exact session, consent, local revision and target comparison. Queued edits can be replaced or cancelled. Epoch-fenced recovery handles uncertain uploads and withdrawal after a value becomes secret without replaying its previous value. Decision generations advance after acknowledgement. Unchecked Variables and other section queues remain outside the selected send.

Large integer values retain exact native text across browser editing and comparison/adoption. Saving an unrelated variable preserves untouched integer text. Types remain text, number, boolean, list and local secret. Secret or blocked values have no value diff, send or adopt control. This adapter has no field merge, force, history or autosync control.

## Review steps and expected result

1. In an isolated matching candidate, save a harmless text value such as `demoGreeting = "Hello"`. Saving alone should stay local.
2. Open Variables → Changes when the host announces support. Review the saved local/Cloud comparison and choose only the intended row for Send.
3. Treat download as a cache update. Review and Apply separately before expecting the local value to change.
4. Use explicit withdrawal to remove a Cloud copy. The local value and its secret classification should remain intact.
5. If session, consent, revision or a target changes, refresh the comparison and review again. Resolve an uncertain outcome through its existing recovery path rather than repeating an upload as a new operation.

These are expected source behaviors, not newly executed production acceptance results.
