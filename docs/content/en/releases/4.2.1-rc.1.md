# TikTools 4.2.1-rc.1 {#tiktools-421-rc1}

## Goal, status and prerequisites {#goal-status-and-prerequisites}

Use this historical candidate record to reproduce the Cloud recovery, Teams and Linux AppImage problems investigated for RC1. It describes the application baseline `338495a9` and a separate backend baseline `6a69c99`. These notes do not establish the current availability of RC1 downloads. Check the [published release assets](https://github.com/nglmercer/TikTools-app/releases) before choosing an installer.

The recorded candidate used locally built Linux AppImage, DEB and portable packages while Actions was disabled. It did not include a newly built Windows installer. Keep a backup and an isolated copy of the affected profile for migration testing. Collaboration and Cloud section recovery remain experimental.

## Changes in this candidate {#changes-in-this-candidate}

- Settings retains account/session and diagnostics; Plugins owns its catalog, search, Changes and installation actions. Templates and profiles stay in Automations.
- The shared Changes panel distinguishes a failed comparison from a successful empty result. The Plugins section sends its own selections/settings while retaining other queues and cached downloads.
- Migration tolerates a missing implicit bundled-plugin directory, keeps explicitly configured paths strict and identifies missing package IDs for reviewed repair. Pending edits and conflicts are retained.
- Teams distinguishes enrolling this PC as a host from selecting a host on another PC. Nickname invitations bind the selected recipient, with host approval still required.
- Optional guided help follows setup state. Linux packaging includes WebKit helpers, GStreamer plugins and the scanner for subsequent media checks.

## Reproduce and inspect the expected result {#reproduce-and-inspect-the-expected-result}

1. Record the displayed version and operating system. Open Plugins → Changes and keep the exact error and request ID if loading fails.
2. In the copied profile, preview migration and review the exact missing package IDs before repair. Preview again afterward; pending edits and conflicts should still be present.
3. In Teams, enroll the current PC before testing its Start control. Selecting another PC's host should not authorize starting this one.
4. Check AppImage startup and then audio/video separately. Reaching the frontend alone does not establish successful media playback.

Nickname search and recipient-bound invitations require backend `6a69c99` and migration `20261113000001_remote_invitation_recipients.sql`. Installing this candidate does not deploy that backend.

## Recovery and evidence limits {#recovery-and-evidence-limits}

If a comparison fails, retain the native reason and retry through the supported panel. Do not delete pending state or infer successful migration from a compatibility check. Collect version, action and redacted diagnostic details using the [troubleshooting guide](../user/preferences/troubleshooting.md).

The original record reports frontend, sync-engine, recipient-isolation and two-host native/relay checks at its baseline. Those dated checks are not fresh production validation. The historical SQLite lock holder was not identified. At RC1, Variables and Overlay Cloud adapters were unfinished, and Automations compared a local reference. Read [later candidate notes](4.2.1-rc.3.md) and the [current Changes guide](../user/cloud/changes.md) for subsequent scope.
